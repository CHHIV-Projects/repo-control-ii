## 4. Architecture / Integration Notes

The thin shim is preferable to a copied, versioned adapter bundle because it
reuses the established central implementation and avoids duplicated lifecycle,
repository, prompt, and authorization checks. Each generated registration
contains explicit target identity constraints; these constraints are not
authority. Every invocation still calls canonical `repoctl.cli coder-context`
for the event worktree. No separate registry, authorization cache, installer,
or service was introduced.

The preview shapes match the existing Copilot and Codex registration
structures and identify their established repo-local config paths. Generated
arguments identify an expected root/key/ID but do not modify those files or
alter their trust. The trusted interpreter and source must remain available
at the reviewed central paths. Normal host project discovery and trust review
remain separate requirements.
