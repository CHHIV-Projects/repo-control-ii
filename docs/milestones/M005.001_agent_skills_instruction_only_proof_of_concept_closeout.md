Fresh chats used the same actual Copilot SDK host, without specifying another model or creating a Git worktree. All test prompts prohibited edits, Git mutation, real workflow submissions, manufactured production incidents, delegation and changes to user configuration.

The six scenarios were **non-authoritative simulations**: models returned concrete expected commands/actions and stop states, rather than issuing them. This tests procedural delivery and model output, not actual CLI execution of each lifecycle transition. The experiment does not establish that skills enforce permissions.

### Context and benefit gate

This is an inventory comparison, not a measured session input total.

There is no legitimate subtraction of mandatory governing rules in this first-stage experiment. Skills package useful ordering but also duplicate existing procedure. Six scenarios share one context batch per condition; they are not six independently randomized cold starts. Per-scenario token, tool-call or latency savings cannot be manufactured by dividing a shared read count by six.

The proposed four-of-six benefit threshold and non-increasing median actual input context are not established. Any trial-specific reduction in repeated view calls must be separated from tool-output truncation and differing read chunk sizes, not attributed automatically to skills.
