## Required deliverables (bounded)
1. **One read-only document-access facade.** Define/implement an explicit provider interface with at least two adapters: SQLite revision provider using caller-supplied *disposable* M010.005 fixture DBs; and allowlisted current/historical Git-file provider using caller-supplied test repositories or controlled read-only source contexts. Return stable repository/document/revision IDs, logical type, original name/path, full-content SHA-256, version/Git provenance when available, source kind, authority class, draft/approved/historical state, and original milestone identifier as text. A Git file and imported DB revision representing identical historical content may be cross-linked/deduplicated in the view, but must never lose their source identities or silently imply different authority. No arbitrary filesystem paths or SQL supplied by clients.
2. **Legacy coverage without fictional lifecycle history.** Discover existing valid Git milestone prompts/closeouts, archived context/planning documents, and historical documents under the current allowlisted historical roots; preserve original names and milestone identifiers including older forms such as `12.65.0` rather than forcing `M###.###`. Historical documents with no workflow/approval record are labeled **historical evidence**, not current approved authority. Do not synthesize past approvals, event-time hashes, transaction boundaries, or milestone closures. Git-backed current role-mapped governing documents retain their existing authority; archived prior versions are distinct. Do not recursively scan unrelated directories, follow unsafe links, or pull arbitrary external URLs.
3. **Repository-aware discovery and search.** Provide `list/search` with filters for repository, milestone ID/text, document class, authority/source/status, and keywords/content. Search should work across both provider types, return deterministic stable ordering, avoid duplicate/missing records during pagination, expose the result's source/provenance, and be practical for ordinary Repo Control document volumes. SQLite may use an appropriate simple text index; any derived catalog/index for legacy Git is explicitly rebuildable and version-bound, not an additional authority. No hardcoded maximum number of documents eligible for a query. A bounded result page or bounded work budget is acceptable only with explicit `has_more`/continuation and accurate `limited`/`omitted`/`total_count_complete` semantics; **never claim an exhausted or complete search while unexamined eligible documents remain**. Either continue candidate enumeration via a stable cursor or return an explicit incomplete result that can resume to eventual completion. Return an explicit error rather than falsely claiming completeness if a source cannot be enumerated.
4. **Exact versions and full document extraction.** Support `get` for exact immutable revision/Git blob or labeled current working-tree version, `read_page` with bounded UTF-8-safe offsets and a stable content hash/cursor, `compare` exact two versions, `export` single/bounded multi-select Markdown plus a manifest of IDs/bytes/hashes/authority and source metadata. Complete source bytes must be recoverable by following all pages; no silent truncation. Validate stale/foreign cursors, missing versions, changed worktrees, wrong repository IDs, duplicate/conflicting source identities, path traversal, symlink escapes, unauthorized file classes, and overly large/malformed requests. An export with missing referenced local attachments must disclose that limitation, not silently imply completeness.
5. **Document Library UI / agent-facing interface.** Provide a small, usable repository-aware view or independently testable UI component capable of browse/filter/search/open exact revision/compare/download, using only the read-only facade. Add narrow, provenance-rich Architect read-only retrieval and Coder document-read/search adapters that can request complete exact revisions through paged results; preserve independent approval roles and Coder Git prohibition. Existing `repo_prompt`, `repo_closeout`, `repo_document`, `repo_history_search/document`, `coder-context`, and ordinary browser workflows must retain current behavior. It is acceptable to deliver **explicitly fixture-gated/test-injected adapters/components rather than activate new live endpoints**; do not expose fixture DB selection, arbitrary paths, or unapproved SQL through a production HTTP/MCP/CLI route. Document exactly what remains to be connected at cutover. No new production live database or service feature flag allowing an older SQLite runtime to be mistaken for eligible.
6. **Original artificial-limit acceptance test (mandatory).** Construct a deterministic historical corpus with **at least 548 eligible documents** split across realistic Git/SQLite providers, with distinctive matching records deliberately located **past candidate 300**, with different repositories, legacy milestone numbering, and historical/current authority classes. Run full enumeration and a selective search; page through every result and assert no invisible tail matches, missing/duplicate records, invalid authoritative labels, cursor cross-contamination, or false completeness. Verify exact-path/full-content retrieval and export for tail records even when first-page results omit them. Include at least one test with >548 matches to prove no 548 hard cap. These figures are historical regression fixtures, NOT newly adopted limits. Preserve legitimate per-call page/byte/time bounds with transparent continuation. Report searched vs returned coverage and how incomplete/failed source scanning is surfaced.
7. **Targeted retrieval efficiency characterization.** Compare a few representative retrieval tasks between current file/historical lookup and the new indexed/structured interface using equivalent fixture data. Record read/query latency, candidate counts, tool-call/page count, relevant evidence bytes/estimated tokens (with the documented token-estimator method), and retrieval accuracy/completeness. No artificial SLO, no claim that SQLite automatically reduces model latency, and no extensive performance/recovery campaign. The main proof is complete, correct discovery and useful targeted retrieval.
8. **Runtime and isolation.** Keep M010.005 caller-supplied/disposable fixture store; Linked SQLite 3.45.1 in current .venv remains **NOT PRODUCTION ELIGIBLE** against conservative fixed-version floor 3.51.3 (or explicitly verified backport). 9. **Tests, regression and closeout.** Add focused tests of two-provider listing/search/pagination, document ID and exact revision, text paging, comparisons and export manifests, source/authority correctness, legacy corpus, end-of-scan continuation, collision/path controls, and Architect/Coder adapter content parity.
