## 1. Executive Result

Implemented a read-only Git Review page in the existing Flask application. It shows repository identity, branch, HEAD, working-tree state, upstream/ahead-behind information with a local-ref freshness caveat, operation/conflict state, changed paths grouped by Git status, and a selected file's bounded evidence.

Tracked diffs are shown separately as **Staged — index vs HEAD** and **Unstaged — working tree vs index**. Untracked regular text files receive a bounded preview; binary, undecodable, symlink, unavailable, and too-large-to-complete previews are explicitly identified. Diff output limits, timeouts, path identity handling, whitespace diagnostics, and Git errors are visible rather than silently interpreted as clean or complete.

The new route does not call milestone-status generation, scan/snapshot generation, or any stage/commit execution/planning service. No Git mutation capability was added. All 174 tests pass.

## 3. Implemented User Workflow

The browser shell navigation retains **Dashboard**, **Workflow**, and **Git Review**. Legacy Context, Snapshots, Comparisons, and AI Review links are removed from the primary navigation; their routes and implementations remain intact.

1. Open Git Review and see repository path, current branch or detached-HEAD state, HEAD, working-tree summary, upstream and local ahead/behind counts, freshness caveat, and detected in-progress Git operation.
2. Review changed files grouped with human-readable labels (for example, **New / untracked** and **Staged + additional unstaged changes**) and the native Git XY status displayed as secondary evidence. Rename/copy entries retain their source path and status.
3. Select a path to inspect only that path. The selection is represented by a URL-safe token derived from its filesystem bytes and is resolved against the current status inventory; user-provided path text is not passed through as a Git pathspec.
4. Review independent staged and unstaged patches, an untracked preview, or an explicit conflict/binary/unsupported/incomplete explanation.

The page is marked **READ ONLY** and contains no mutation controls.

## 4. Backend / Git Commands Used

The new service reuses `inspect_git_state` and the existing porcelain-v2 status parser. `inspect_git_state` accepts an optional status-output limit; existing callers retain prior behavior. The parser now decodes pathname fields using filesystem surrogate handling and sorts them by filesystem bytes, preserving non-UTF-8 paths without confusing them with metadata.

Read-only commands used by the service:

- `git status --porcelain=v2 --branch -z --untracked-files=all`
- Existing state probes for `rev-parse`, current branch, and Git in-progress-operation markers
- `git diff --no-ext-diff --no-textconv --no-color --no-renames --unified=3 -- <literal pathspec>`
- `git diff --cached ... HEAD -- <literal pathspec>`
- Corresponding `git diff --check` calls for staged and unstaged evidence

No remote URL is displayed. No network operation is performed. Git commands are passed as argument arrays; shell interpolation is not used. External diff programs and textconv are disabled for displayed patches.

Subprocess output is collected incrementally using bounded pipes, with `GIT_OPTIONAL_LOCKS=0` to prevent Git's optional index refresh writes during inspection. A timeout or status inventory overrun is an explicit error; an over-limit diff is visibly incomplete rather than parsed or shown as complete.

## 5. Git-State Presentation

The page displays:

- Repository root, attached branch or detached HEAD, full HEAD OID, and a human-readable working-tree state.
- Upstream ref and ahead/behind numbers when local tracking-ref data is available.
- A freshness warning: these counts use local tracking refs; no remote refresh was performed.
- Detected active Git operations and conflicts.
- Path-level staged, unstaged, staged-plus-unstaged, untracked, rename/copy, and unmerged distinctions, using readable labels with native Git status codes alongside them.

If status collection fails, the page returns a service-unavailable response with a bounded error and states that no partial inventory is shown as complete. It does not fall back to “clean.”

## 6. Diff Presentation

For a tracked changed path:

- Staged evidence compares **index vs HEAD**.
- Unstaged evidence compares **working tree vs index**.
- A path with both kinds displays two separate patches; neither is merged into a synthetic diff.
- Rename/copy pathspecs include the current and original path with Git literal-pathspec syntax.
- Deleted or otherwise unavailable filesystem paths still use Git's index/tree diff evidence; filesystem metadata is reported as unavailable where appropriate.
- Conflicted paths explicitly state that ordinary patch evidence may be incomplete/unsuitable. No absence of a normal patch is described as “unchanged.”

Output is capped at **128 KiB per diff command**. If exceeded, Git is stopped and the returned bytes are marked incomplete. Diff commands have a **10-second timeout**. The subprocess collector also caps stderr at **16 KiB**.

## 7. Untracked File Behavior

Selected untracked regular files are read directly for preview; they are not passed to `git add` and are never added to Git.

- Maximum preview: **64 KiB** per file, read incrementally with at most one byte beyond the display cap to determine truncation.
- Small valid UTF-8 text is shown as a complete preview.
- Larger text may show a capped preview with an explicit incomplete warning.
- Binary content, invalid UTF-8, symlinks, non-regular files, unavailable paths, or paths resolving outside the repository receive metadata/reason text instead of a content preview.
- Opening a symlink is prohibited; a no-follow open and regular-file check are used.

## 8. Binary / Large / Unsupported Behavior

- Git's binary diff marker produces an explicit “binary content; text patch is not available” message, not an empty/no-change conclusion.
- Large diffs are bounded per command and labeled incomplete when their output cap is reached.
- Undecodable tracked diff output is not rendered with replacement characters; the page reports that text evidence is unavailable.
- Untracked preview reports path, file type/size where available, and a specific binary, UTF-8, file-type, safety, or availability reason.
- Conflicts are identified from Git's unmerged status record and presented separately from ordinary staged/unstaged patches.

No binary payload is emitted through `git diff --binary`.

## 9. Whitespace Signal Behavior

Each available staged/unstaged patch has a separate `git diff --check` result. Recognized whitespace diagnostics appear as **Whitespace warning** with Git's bounded diagnostic text; an output overrun is labeled incomplete. No warning is presented as **No whitespace issue detected**.

Whitespace diagnostics do not suppress the normal diff. They do not label a change harmless, accidental, safe to discard, or semantically insignificant. A non-warning command failure remains an explicit service error.

## 10. Error / Unknown-State Behavior

- A truncated status inventory is rejected as incomplete; partial entries are not displayed as the full repository state.
- Git command failure and timeout are surfaced in the Git Review page; neither becomes a clean state.
- Upstream-not-configured and upstream-ref-unavailable states remain distinct from zero ahead/behind.
- Detached HEAD and active operations are visible.
- A selected file that has disappeared from the latest Git status returns a not-found response instead of using stale path data.
- Non-UTF-8 pathname bytes are preserved internally with filesystem decoding, escaped for display (for example, a raw `0xff` byte displays as `\xff`), and represented in selection tokens using their original filesystem bytes.
- Whitespace-check warnings are distinguished from actual command failures.

## 16. Known Limitations

- A `git diff --check` signal follows Git's configured whitespace rules; it cannot establish semantic safety or intent.
- Git can establish repository state and content, but cannot by itself explain who changed a path, whether the change was accidental, or whether it belongs to a milestone.
- Ahead/behind information can be stale because no remote refresh is performed.
- Diffs beyond the output cap are only partial evidence; the UI marks them incomplete and this milestone provides no paging or downloadable patch.
- The review page is subject to the existing loopback/SSH access model. Repository diff content is sensitive to anyone who can access the UI.
- Existing inherited web mutation routes remain outside this change and were not removed or redesigned.
