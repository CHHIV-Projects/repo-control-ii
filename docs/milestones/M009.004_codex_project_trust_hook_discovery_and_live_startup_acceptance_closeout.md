context, identity/prompt mismatch, or incoherent lifecycle returns
`INVALID_NO_AUTHORITY` or `NO_AUTHORITY` with a stop instruction.

## 8. Known Limitations

- This is acceptance for one installed VS Code Codex Remote SSH host and one
  exact repository only.
- The exact Windows VS Code build and effective Windows-side policy remain
  unknown.
- Hook context is point-in-time input, not a fail-closed filesystem/tool/Git
  permission boundary.
- The adapter cannot enforce a stop when a host fails before invoking or
  delivering the hook.
- Changing the definition requires a new supported UI review/trust action.
- Live `resume`, `compact`, `clear`, and `fork` delivery is unverified despite
  fixture coverage.
- The private receipt was intentionally deleted; its invocation facts remain
  Coder-reported workflow evidence, while marker delivery/order persists in
  the thread record.

Repository Intelligence: **NOT USED** — the decisive questions were installed
host discovery, trust, native invocation, and pre-response delivery, which a
static source graph cannot establish. A refresh was considered but not needed;
no graph receipt, query, or rating was manufactured. Source review, focused
fixtures, host config metadata, PO UI observations, and live thread ordering
were the material evidence.
