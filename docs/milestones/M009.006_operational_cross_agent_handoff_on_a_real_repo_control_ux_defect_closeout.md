## 2. Resulting Behavior

Before the repair, a WAITING `resolve_and_resume` browser submission containing
CR or CRLF reached strict workflow validation unchanged and returned HTTP 400.
The browser route now converts CRLF and CR line endings to LF only for that
combined resolution summary. Existing LF, TAB, and ordinary text are preserved.
The unchanged lifecycle validator still rejects U+0001 and other unsupported
controls, and a rejected request records no event.

The verified root cause is the direct passage of browser-posted CR/CRLF through
the field boundary into validation that permits LF and TAB but rejects other
characters below U+0020. This conclusion is supported by source inspection and
the executable before/after regression, not solely by the original parking-lot
hypothesis or Copilot's report.
