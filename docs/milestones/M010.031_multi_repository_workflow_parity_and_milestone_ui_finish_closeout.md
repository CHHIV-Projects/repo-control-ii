## 4. Architecture / Integration Notes

The recurring failures were not caused by SQLite scale. They came from
combining stable authority, mutable request context, filesystem permissions and
recovery evidence into composite gates. A safe user action changed one field
and invalidated an unrelated proof.

The implemented boundary is now:

1. recovery eligibility is whole-database authority plus database identity;
2. repository authorization is an independent exact registry check;
3. repository and milestone selections are request/audit context;
4. systemd grants only reviewed Git metadata and selection write surfaces; and
5. unverified imported history is readable but never promoted to authority.

The remaining architectural simplification is to retire the writable JSON
selection pointer as an authority prerequisite in managed mode. SQLite should
remain the sole selection authority; any compatibility file should become a
derived, replaceable projection. Deployment names and repair scripts should
also converge into one versioned production package after this arc.

Repository Intelligence: NOT USED — direct source, exact records, effective
systemd configuration, runtime health, service logs, browser evidence and
executable tests answered the structural/runtime questions. Its status was not
needed and no refresh was attempted.
