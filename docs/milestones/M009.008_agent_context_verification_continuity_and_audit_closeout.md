## 2. Resulting Behavior

| Trigger | Required behavior |
|---|---|
| NEW | Resolve live repository, milestone, authorization, procedure, overlay, and Git boundary before consequential work. |
| WARM | Preserve valid context; do not repeat full bootstrap or create redundant records. Recheck focused authority when a material boundary changes. |
| HANDOFF | Perform NEW verification, then reconcile prompt, approved decisions, questions/bugs, test/closeout evidence, and read-only HEAD/status. |
| AUTHORITY TRANSITION | Recheck after a repository/milestone, prompt/approved instruction, lifecycle/authorization, or applicable procedure change. |
| RECOVERY | Re-resolve authority after context loss or suspected invalidity; do not infer continuity from chat history. |

The Coder recording interface is:

```text
repoctl coder-verify --trigger {NEW,HANDOFF,AUTHORITY_TRANSITION,RECOVERY} \
  --expected-repository-key <key> --expected-repository-id <id> \
  --expected-repository-root <absolute-path> --expected-milestone-id <id> \
  --acknowledge-git-boundary
```

The command rejects mismatched identity and milestone assertions. It appends an audit-only `context_verification_recorded` event and leaves lifecycle unchanged. Results are `VERIFIED`, `BLOCKED`, or `PARTIAL_UNVERIFIED`; corresponding CLI exit codes are 0, 3, and 4 (identity/validation errors return 2; unexpected errors return 1). Identical consecutive trigger/snapshot/acknowledgement submissions are deduplicated.

The bounded snapshot includes repository key/ID/root; milestone and prompt path/hash; lifecycle, authorization, open conditions, lock-in/dispatch digests, closeout and reported test evidence; canonical/installed procedure and overlay identity; and Git HEAD/branch/working-tree state. It excludes prompt bodies and conversation transcripts. The record marks trigger and session identity as agent-reported/unverified, the snapshot as Repo Control-observed local state, and provider delivery as unverified.
