# 2. Primary Objective

Deliver a working ChatGPT-to-Repo-Control **read-only Architect integration** that allows ChatGPT to retrieve current Repo Control evidence without manual packet copying.

The expected end state is:

```text
Product Owner asks Architect a Repo Control question
        ↓
ChatGPT invokes one or more MCP tools
        ↓
Secure MCP Tunnel forwards to henderson-server1
        ↓
local MCP adapter calls fixed Repo Control GET endpoints
        ↓
ChatGPT receives fresh bounded evidence
        ↓
Architect reasons over current facts
```

No Git mutation, workflow mutation, arbitrary filesystem access, shell access, or arbitrary HTTP proxying is allowed.

This milestone has two explicit gates.

## Gate A — Secure MCP Tunnel Compatibility Proof

Before implementing the Repo Control adapter, prove that the Product Owner's actual ChatGPT environment and Platform permissions support the intended tunnel path.

```text

```

If Gate A fails:

```text
STOP
record exact failure
retain manual packet transport
do not build the Repo Control adapter
```

Do not compensate by exposing Repo Control publicly.

## Gate B — Repo Control Read-Only Integration

Proceed only after Gate A passes.

Gate B implements the narrow MCP adapter, systemd supervision, bounded logging, tests, and live ChatGPT acceptance.


# 8. MCP Adapter Design

Implement a small adapter whose only purpose is to expose named read-only tools backed by the existing Architect API.

Prefer:

```text
small Python implementation
minimal dependencies
stdio transport under tunnel-client
no network listener
no database
no cache
no repository parser
no duplicate workflow logic
```

The adapter must not become a second control plane.

Preferred model:


```text

not require interactive login
not depend on VS Code
```

# 15. Identity and Authorization

This milestone does not attempt person-level identity inside Repo Control.

The trust chain is:

```text
ChatGPT workspace/app authorization
        ↓
OpenAI tunnel association
        ↓

        ↓

        ↓
```

Repo Control may treat the local adapter as the transport identity.

Do not claim that Repo Control knows which individual human made a request unless the transport actually provides verifiable identity.

- Secure MCP Tunnel is unavailable in the Product Owner's actual account/workspace;

- the adapter cannot remain GET-only;
- credentials cannot be stored safely outside the repository;
- Repo Control must bind beyond loopback;
- person-level authentication becomes mandatory to proceed;
- the implementation would require a new database;
- Harpoon proves materially simpler and fully supported, changing the selected architecture;
- repository isolation cannot be preserved.

Do not silently change the architecture.
