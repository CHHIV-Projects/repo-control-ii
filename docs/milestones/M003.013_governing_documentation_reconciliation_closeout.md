## 4. Accepted Architectural Implications Recorded

- **Bounded Architect evidence:** fixed read-only tools provide selected repository/milestone, prompt, workflow, closeout, Git, recorded evidence, governing-document, and review information. Natural requests authorize only the minimum needed evidence, not arbitrary shell, filesystem, repository, Git, lifecycle, or Product Owner operations.
- **Separate dispatch channel:** PROMPT / INSTRUCTION / RESPONSE submissions create PENDING proposals. Only Product Owner approval authorizes applicable guidance; pending/rejected proposals do not. Dispatch approval itself creates no lifecycle event or Git mutation.
- **Canonical prompt transport:** Architect -> Repo Control -> Product Owner review -> server-derived canonical prompt. Dispatch Approve & Save Prompt is not lifecycle Approve & Start and does not select, approve/start, stage, commit, or push. Product Owner review/commit should normally precede implementation.
- **Local Coder boundary:** context/status plus bounded question, bug, validation-evidence, and closeout commands; no Coder MCP or generic event command. Approved INSTRUCTION/RESPONSE guidance is a separate context section, not lifecycle authority. Coder submissions retain `actor_role="coder"` and `po_approved=False`.
- **Six-phase lifecycle:** PLANNING, READY, IN_PROGRESS, WAITING, REVIEW, CLOSED. Events remain explicit and ordered; tests, closeout presence, and Git state do not automatically advance phase.
- **Single-user compression:** Approve & Start records `prompt_approved` then `implementation_started`; Resolve & Resume records the applicable answer/resolution, optional separate `lock_in_approved`, then `implementation_resumed`; Accept & Close records `acceptance_recorded` then `milestone_closed`, retaining supported prior-acceptance reuse.
- **Browser authority:** deliberate normal Product Owner action buttons replace redundant actor/confirmation controls, not server validation or role boundaries. Ordered event sequences persist atomically.
- **Polling/stale state:** untouched forms refresh from server state; edited forms preserve text and block stale submission. No WebSocket/event bus exists. M003.010's automatic REVIEW observation occurred after runtime reload, not during its earlier old-runtime Q2 WAITING transition.
- **Operational sidecar:** only the active workflow sidecar is expected modified/untracked state by itself. A newly materialized prompt is not a general exemption; any other unexplained dirty path remains a blocker.
- **Git authority:** coding agents must not stage, commit, push, tag, merge, rebase, reset, stash, clean, switch/checkout, create/delete branches, or mutate remotes. Product Owner Git operations remain separate from dispatch and workflow events.
- **Control-plane identity:** Repo Control owns authority, deterministic state, explicit workflow, and bounded evidence routing. Replaceable specialized tools own their engines; Repo Control is not an AI project manager or a giant bespoke agent framework.
