## 3. Contract Overview

Transport is local HTTP JSON in the existing Flask service, below
`/api/architect/v1`. The service continues to bind only to `127.0.0.1` or
`localhost` under the existing host validation; no listener configuration or
systemd unit was changed.

All routes are GET-only:

| Endpoint | Contract |
|---|---|
| `/status` | Repository identity, registry generation, active milestone selection, and lifecycle summary if a milestone is selected. |
| `/milestone` | Selected milestone, lifecycle, waiting reason, prompt/closeout/workflow status, latest binding lock-in, open conditions, and next authorized action. |
| `/prompt` | Full authoritative selected prompt, with source type/path, UTF-8 byte size, and `truncated: false`. |
| `/workflow` | Phase, waiting state, bounded recent events, binding lock-ins, unresolved conditions, and next authorized action. |
| `/closeout` | Closeout status/path/size and bounded full content when present. A closeout required by REVIEW but missing or mismatched is an explicit `required_missing` state. |
| `/git` | Branch, HEAD, local upstream/divergence, clean/dirty classification, and bounded status paths. |
| `/evidence` | Bounded recorded test-result events, labeled `reported`. |
| `/documents` | All supported governing-document roles, including unconfigured roles, with configured path and present/missing/unsafe/oversized status. |
| `/documents/{role}` | Bounded full content for one configured allowlisted role. |
| `/review` | Bounded review summary with milestone/workflow state, lock-ins, unresolved conditions, Git state, reported test evidence, configured-document metadata, and source references. It does not embed prompt or governing-document contents. |

Every successful response includes `contract_version: "1"`, server-resolved
repository identity/path/id/generation, current selection status and identity,
resource `data`, and `source_scope`. Error responses use
`{"contract_version":"1","error":{"code":"...","message":"..."}}` and the
appropriate HTTP status. Responses are serialized as UTF-8 JSON, have
`Cache-Control: no-store`, and are capped at 512,000 bytes.

Optional query preconditions are `expected_repository_key`,
`expected_generation`, and `expected_milestone_id`. Supplied values are
validated and compared with request-time state; stale repository generation,
repository selection, or milestone selection returns HTTP 409. Unsupported or
duplicate parameters are rejected. No caller-supplied filesystem path or
repository path is accepted.

## 4. Repository and Milestone Contract

Repository key, display name, absolute path, and repository ID come from the
active `RepositoryEntry` in the existing registry. `registry_generation` is
the current in-process registry generation, which increments when the active
repository changes. It is process-local, resets on service restart, and is not
a durable registry revision.

The selected milestone comes from `load_milestone_selection()` and its
repository-scoped external pointer, then is validated against current
discovery. No filename ordering or caller-supplied ID is used to choose the
active milestone. The response identifies milestone ID and prompt path;
selected-milestone endpoints return a JSON error if no valid selection exists.
`/status` remains queryable without a selection and reports `selection.status`
plus null milestone identity.

The milestone view exposes lifecycle phase, current waiting category/reason,
event count, latest binding lock-in, bounded open conditions, next authorized
action, prompt metadata, closeout presence/path/state, and workflow
sidecar presence/path. A missing closeout in REVIEW is not treated as
acceptance or silently omitted. If a previously submitted closeout has gone
missing or no longer matches discovery, `/closeout` returns `status:
required_missing`, `lifecycle_status: invalid`, and a stable contract error;
other workflow endpoints report the invalid ledger rather than inferring a
phase.

## 5. Prompt, Workflow, Closeout, and Evidence

Prompt and closeout content are read using M003.003's repository-relative
source validator. Symlinked/out-of-repository paths, unreadable content,
invalid UTF-8, obvious private-key material, and sources larger than 128,000
bytes are rejected. Content responses report source type, source path, byte
size, and explicit non-truncation. No partial authoritative content is
returned.

Workflow state is read through the existing lifecycle parser. Sidecars are
validated with the existing 5 MB safety cap and also checked for safe
repository containment and private-key markers before their derived evidence
is exposed. The source is labeled as the workflow sidecar, or as a derived
empty workflow when no sidecar exists.

Workflow event summaries, binding lock-ins, open conditions, and test evidence
are separately bounded to 30 events with total, returned, and omitted counts.
Events include IDs, timestamps, event types, source-reported actor role,
summary, and available related/evidence fields. Actor roles are explicitly
not authenticated. `decision_recorded` remains non-binding;
`lock_in_approved` is represented as binding only when the ledger marks it
binding. Recorded test outcomes are labeled reported and are not presented as
independently verified machine observations.

## 6. Git Contract

Git state reuses `inspect_git_state()` and exposes local branch, HEAD, upstream
configuration and divergence when available, working-tree classification,
staged/unstaged/untracked/unmerged counts and paths, and in-progress Git
operations. Each path category returns at most 40 paths plus total,
returned, and omitted counts.

The response explicitly marks upstream data as based on local tracking refs,
sets `remote_refresh_performed: false`, and includes an observation timestamp.
No fetch, remote contact, diff generation, or test execution occurs. Git
inspection failures return a stable JSON `git_inspection_failed` error rather
than a success-shaped fallback.

## 7. Governing Document Contract

Governing document roles are discovered only from server-side registry
configuration. The API returns all supported role names, with unconfigured
roles explicitly marked. Configured paths are repository-relative and
server-controlled; configured missing, unsafe, unreadable, and oversized
sources are surfaced. Content retrieval takes a role name only and never
accepts a path.

## 8. Error Contract

The implementation returns explicit JSON errors/states for:

| Condition | Response |
|---|---|
| No selected milestone for a milestone-dependent query | HTTP 409, `no_selected_milestone`; `/status` reports no selection normally. |
| Repository generation/repository/milestone precondition mismatch | HTTP 409 with a stale-state error code. |
| Invalid/stale selection pointer or missing selected prompt | HTTP 409 `stale_milestone_pointer` or HTTP 404 `missing_prompt`. |
| Malformed workflow sidecar | HTTP 422 `malformed_workflow_sidecar`. |
| Missing/mismatched closeout required by workflow history | `/closeout` returns explicit `required_missing`; other workflow-dependent views return HTTP 409 `required_closeout_missing`. |
| Missing, unsafe, unreadable, or oversized prompt/closeout/governing document | HTTP 404/422/413 with a stable source error. No partial content is returned. |
| Unsupported/unconfigured document role or query parameter | HTTP 404/400 with a stable error code. |
| Git inspection failure | HTTP 503 `git_inspection_failed`. |
| Aggregate JSON response above 512,000 bytes | HTTP 413 `response_oversized`. |
| Unexpected application failure under the API namespace | HTTP 500 JSON `unexpected_error`. |

Invalid repository-registry configuration is rejected when the application
loads its existing server-controlled registry; no API route can bypass that
startup validation.

## 9. Security and Access Boundary

The API is hosted by the existing loopback-only service. The accepted Windows
access path remains an SSH local tunnel to the Linux loopback listener. The
implementation does not bind to a LAN/public interface, enable CORS, weaken
the existing host validation, add a public route, or add credentials.

GET requests do not mutate state, so CSRF tokens are not required for these
endpoints. Same-origin browser policy still applies and CORS is not enabled.
There is no independent caller authentication or authenticated role identity:
local processes/users able to access the service, including users authorized
through the existing SSH tunnel, can read the exposed project evidence.
Within this milestone, the bounded read-only data exposure is accepted only
inside that existing loopback/SSH trust boundary. Do not expose the service
directly to a LAN or the public Internet.

## 10. Read-Only Evidence

## 14. Known Limitations

- No direct ChatGPT/OpenAI integration.
- No Coder write/submission tools or other workflow mutations.
- No authenticated role identity or caller authentication beyond existing
  loopback/SSH access trust.
- No multi-agent writes or coordination.
- No LAN/public exposure.
- No repository-intelligence integration.
- No test execution orchestration; the API returns recorded evidence only.
- No atomic multi-source snapshot guarantee across repository files, the
  selection pointer, and Git. Each request freshly reads current state, but
  external edits can occur while one response is being assembled.
- Registry generation is process-local and does not represent registry-file
  revisions.
- Configured content is individually limited to 128 KB; sidecars to 5 MB;
  event summaries to 30; Git paths to 40 per category; complete JSON response
  to 512 KB.
