The active systemd process (PID 1464 at inspection time) was running as user

The interactive shell had Git command-line configuration variables set; the

reported terminal Push success was not independently reproduced; its exact

Repo Control's remote Git subprocess explicitly:

- sets `GIT_TERMINAL_PROMPT=0`;
- sets `GIT_ASKPASS=/bin/false` and `SSH_ASKPASS=/bin/false`;
- uses `stdin=DEVNULL`;
- invokes SSH with `BatchMode=yes`.

These controls are intentional and must remain. The active service environment
does not inherit the interactive shell's askpass helper.

## 7. Approved Authentication Model and Local Setup

The Product Owner approved and registered a dedicated Ed25519 **read/write
Deploy Key** for only `CHHIV-Projects/repo-control-ii`, stored under user
`chuck` at:

```text
/home/chuck/.ssh/id_ed25519_repo_control_github
```

The Deploy Key is repository-scoped and has **Allow write access** enabled
only for the Repo Control II repository so the existing Push operation can
publish. Neither other-project key was reused.

For unattended systemd Push without a persistent SSH agent, a passphrase
protected private key is not available to the service at boot. The simple
service-compatible model is therefore a dedicated passphrase-free key readable
only by `chuck` (private-key file mode `600`; `.ssh` directory is mode `700`).
This grants the service account the ability to push to the one repository and
carries the corresponding at-rest key risk. The key was generated with an
empty passphrase as approved. A passphrase-protected key would require a
separately designed reliable unattended agent model and is not recommended for
this bounded milestone.

The key is at `/home/chuck/.ssh/id_ed25519_repo_control_github` (mode `600`,
owner `chuck`). Its public-key fingerprint is
`SHA256:La5j/LfT7DPG4En5vr+TKjNRWaYrV7wL3xkH4A75nvA`. No key contents are
included in this closeout. The existing SSH config was preserved and appended
with a dedicated alias:

```sshconfig
Host github-repo-control-ii
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_repo_control_github
    IdentitiesOnly yes
    StrictHostKeyChecking yes
```

`ssh -G github-repo-control-ii` confirmed the effective hostname, user, key,
`IdentitiesOnly yes`, and `StrictHostKeyChecking yes`. The SSH config file
remains mode `600`. The existing aliases for the other projects are unchanged.
The Product Owner registered the corresponding public key as a write-enabled
Deploy Key for `CHHIV-Projects/repo-control-ii`; no private-key material was
exposed or stored in the repository.

The Product Owner ran:
