# Milestone M011.001 — Shared Procedure Transaction and Deployment Compatibility

## 1. Scope Completed

Repaired the managed R8 procedure-transaction storage contract and implemented
the approved Product Owner-controlled worktree boundary as one design. The
running browser now uses the existing private service-user transaction store
instead of deriving storage from the intentionally root-owned R8 parent.
Browser Confirm seals an exact request without modifying a worktree; an
inactive same-UID systemd one-shot revalidates and executes only that request
for the selected registered repository.

The implementation preserves the accepted managed SQLite R8 authority,
registry, selection, recovery policy, legacy journals, Git boundary, and
published procedure 1.5.0. It did not update Vocab App or Photo Organizer.

## 2. Resulting Behavior

- `/home/chuck/.local/share/.repoctl-procedure-transactions` is the explicit
  private journal/request root. It remains `chuck:chuck` mode `0700`.
- Missing, inaccessible, incorrectly owned/mode, or symlinked configured
  storage reports `STORAGE_UNAVAILABLE`. Malformed or integrity-invalid
  journal/request content still reports `CORRUPT`.
- Preserved terminal overlay journals remain readable after a later registry
  overlay remap; active recovery remains bound to the current exact mapping.
- Preview and Review are read-only. Confirm stores one exact request bound to
  repository key/ID/path, live selection generation, reviewed plan or recovery
  journal, and target snapshots/hashes.
- `repo-control-procedure-update@<key>.service` runs as `chuck:chuck`, checks
  live repository selection, executes once, and exits. A stale selection fails
  before target writes and permits a fresh review.
- The main service receives only the private journal-root write exception.
  Each inactive repository instance receives the selected repository root only
  for its lifetime; nested `.git`, `docs/context`, and `docs/milestones` remain
  read-only, and every nonselected repository remains read-only.
- An executor death before a journal exists remains retryable. Once an active
  journal exists, status exposes recovery. A separately reviewed Recover may
  supersede only its matching interrupted request and restores exact original
  images.

## 4. Architecture / Integration Notes

The design uses no privileged helper, new daemon, schema migration, authority
cutover, blanket `/home` exception, persistent worktree exception, ACL change,
or permission change. Root `AGENTS.md` requires parent-directory rename rights,
so the approved exception is temporal and limited to the selected one-shot
namespace. Application allowlists, repository identity, reviewed hashes,
current snapshots, confirmation expiry, live-selection revalidation, and
nested systemd read-only mounts constrain the actual operation.

The five installed files are root-owned mode `0644`. The live main service
retains `ProtectSystem=strict` and `ProtectHome=read-only`. All three executor
instances are `static` and `inactive`. Prior configuration was captured under
`/root/repo-control-m011001-before`; undo restores only these five paths and
restarts the same managed R8 service.

Repository Intelligence: **NOT USED** — a final stats query reported `STALE`
because supported source inputs changed, with zero returned structural nodes.
Refresh was considered but not attempted: direct source inspection, exact
filesystem metadata, effective systemd properties, live health, journal
inspection, focused tests, and two real transient-systemd fixture runs answered
the acceptance questions. A refreshed static graph would not replace the
required runtime sandbox and crash/recovery evidence.

## 7. Deviations from Prompt

The first disposable fixture start failed before systemd startup because its
root was correctly non-writable while the unprivileged setup driver initially
needed three pre-provisioned child paths. The script was narrowed to provision
only those exact `chuck`-owned paths; a non-writable-root simulation passed,
and both complete operator runs then passed. Failed fixture evidence was
preserved rather than discarded.

While reading the preserved live store, one historical Photo Organizer terminal
overlay journal initially failed because its former overlay path no longer
matched the current remapped registry path. Compatibility was narrowed to safe
repository-relative paths for terminal evidence only; active journals still
require the current exact mapping. Focused coverage and all three live journal
statuses passed afterward.
