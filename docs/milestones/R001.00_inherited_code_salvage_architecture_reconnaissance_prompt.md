## KEEP Definition

Use `KEEP` when the component:

- provides current demonstrated value;
- aligns with Repo Control II architecture;
- has acceptable coupling;
- is understandable;
- is testable;
- can remain substantially intact.

`KEEP` does not prohibit later cleanup.

---

## REFACTOR Definition

Use `REFACTOR` when:

- the capability is useful;
- important logic is worth preserving;
- current coupling or boundaries conflict with Repo Control II;
- retaining the capability is preferable to replacement;
- a bounded refactor can align it with the new architecture.

The closeout should explain what should be preserved and what should change.

---

## RETIRE Definition

Use `RETIRE` when:

- the capability no longer serves the new product direction;
- it duplicates a better external specialization;
- it primarily supports obsolete Repo Control I assumptions;
- it adds maintenance burden without demonstrated value;
- removal simplifies the new control plane.

Do not recommend immediate deletion merely because something is classified `RETIRE`.

Retirement implementation belongs in a later approved milestone.
