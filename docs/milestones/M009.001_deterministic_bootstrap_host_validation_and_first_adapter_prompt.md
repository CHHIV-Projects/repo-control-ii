## 5. Authority enforcement and security review

Context retrieval, lifecycle authorization, and host filesystem/tool enforcement are three distinct boundaries:

- `coder-context` is authoritative for current Repo Control state; **not** an authorization grant stored in chat.
- Existing Repo Control lifecycle gates continue to control *Repo Control operations*. The adapter must never confer authority to edit files, mutate Git, or run shell commands.
- A supported pre-tool hook can add guardrails, but observed event coverage and failure modes must be documented. In particular, do not claim fail-closed enforcement for a hook whose timeout falls through to normal host permissions.
- Respect Product Owner-owned host permissions/sandbox and Git credentials. Never relax trust controls, auto-approve all tools, or use hook `allow` output to override normal approval simply for tests.
- No Coder stage, commit, push, tag, merge, rebase, reset, stash, clean, branch create/switch/delete, or remote mutation. Do not have the hook itself perform these either.
- If the exact selected worktree/milestone cannot be verified, the adapter must say **NO AUTHORITY** and the Coder must STOP/escalate. A running hook that fails closed at the CLI is not proof the agent itself cannot write; report residual host limitations.
