Graphify's current open-source engine is a credible model-independent structural intelligence subsystem. ## 4. Model-Agnostic Assessment

**Yes for the core code graph.** Changing Copilot, Codex, Claude, Gemini, or another Coder does not inherently require replacing/rebuilding the graph. Rebuild when source/configuration/extractor/schema changes, not merely because the consumer model changes.

Separate the stages:

1. **AST extraction:** local deterministic structural parsing. Symbol resolution is static analysis with limitations, not runtime execution.
2. **Inference/deduplication:** static name/import/call resolution and fuzzy entity merging can infer relationships without an LLM. Optional `--dedup-llm` does invoke a backend; it must remain off for the initial POC. Compare dedup behavior rather than assuming similarly named symbols remain distinct.
3. **Clustering:** graph algorithms, not model reasoning. Record whether Louvain or Leiden actually ran; topology/community stability must still be measured.
4. **Semantic inputs:** docs, images, PDFs, and other media may go to the assistant's model or a configured headless backend. Backend selection may follow available API credentials. A mixed repository must use explicit `--code-only`, not rely on an absent key or a marketing claim of locality.
5. **Assistant wrappers:** skills/slash commands and auto-registration are convenience/orchestration surfaces, not the intelligence source or an architectural prerequisite. Do not install them in this arc.
6. **CLI/MCP retrieval:** operates against the persisted graph. Natural-language `query` is keyword/seed matching plus graph traversal, not a general model answering questions.

Graph evidence and its confidence labels must remain the same for both consumers; models may interpret it differently. See [official architecture](https://docs.graphify.com/concepts/architecture) and [provenance guidance](https://docs.graphify.com/concepts/provenance).

## 7. Concrete Intelligence Value and Reliability

| Question | Evidence/value | Important limit |
|---|---|---|
| Where is a symbol defined, and which file/module owns it? | AST nodes, source_file/source_location, definitions | Duplicate labels require stable IDs/path-scoped lookup; incomplete extraction must not look like absence |
| What imports this module or depends on this symbol? | Import/reference edges and reverse neighborhood | Dynamic imports, aliases, external symbols, and resolver mistakes can leave gaps |
| Who calls this function; what does it call? | Direct extraction plus cross-file call resolution | INFERRED calls are not observed calls; closures, dynamic receivers, Flask registrations and callbacks need ground truth |
| What relates two concepts? | Native shortest path and directed/undirected options | A relationship path is not necessarily a call path; preserve relation type, direction, and confidence |
| Which subsystems are tightly connected? | Communities, cohesion, degree/god nodes | Heuristic architectural grouping; large web/app.py may dominate and must not be mistaken for intended design |
| What might this change affect? | `affected` reverse dependency traversal / changed-file seed neighborhoods | Conservative static impact, not complete runtime blast radius or formal verification |
| Which tests might be relevant? | Test code calls/imports and neighborhood paths | Candidate tests only; not executed coverage or proof of sufficient validation |
| What does a PR touch? | Local MCP PR tools combine GitHub file/diff data with graph communities | Uses gh/network/auth; not an offline query and not needed initially. Repo Control can supply its own verified changed-path seeds later |
| Which docs relate to code? | Semantic extraction and some specialized local references/rationale | Full cross-document/code semantics may require model processing; excluded from initial code-only POC |

Nodes and edges carry source paths; source line locations are available where extracted. Confidence vocabulary is `EXTRACTED`, `INFERRED`, `AMBIGUOUS`, with optional confidence scores and additional metadata. INFERRED does not mean an LLM created the edge, and numeric scores are not calibrated probabilities. Repo Control should preserve the original tier/score, direction, relation, source file/location, producer version, graph identity and freshness; never promote inferred edges to verified runtime facts.

An important direct-JSON hazard is documented in upstream ARCHITECTURE.md: a graph may be serialized with `directed: false` while individual edge arc order or `_src`/`_tgt` carries direction. Naive NetworkX loading or generic undirected traversal can reverse caller/callee evidence. Prefer native query behavior; test directional fidelity explicitly.

## 10. Privacy and Exposure Assessment

This is an architectural privacy/operational assessment, not an exploit audit or a blanket security certification.

- Official docs state local code extraction sends no source to a model and has no telemetry. Source confirms `--code-only` skips semantic files and gates backend selection on actual model work. An indicator search found no telemetry SDK instrumentation; that is not a proof about all code/dependencies.
- Backend auto-detection, optional LLM dedup, cluster labeling, PR triage, document/media semantic processing, ingestion URLs, and hosted Cloud are different data paths. Keep them disabled and provider credentials absent from the POC process.
- Even code-only extraction imports the LLM module. Its optional tiktoken initialization may download tokenizer data on first use if installed. Viewer HTML loads a pinned vis-network script from unpkg.com. These are network dependencies distinct from source upload; an absolute offline claim requires testing with egress denied and an empty controlled cache.
- Query logging is opt-in and local. Use `GRAPHIFY_QUERY_LOG_DISABLE=1`; otherwise queries, paths and optional full responses can be retained outside repository ignore rules. See [configuration](https://docs.graphify.com/reference/configuration) and [querylog.py](https://github.com/Graphify-Labs/graphify/blob/10130e79ed9caf8f60d998073e097531eaa1a395/graphify/querylog.py).
- Respect `.gitignore` plus explicit `.graphifyignore`/exclude configuration and sensitive-file heuristics. They are discovery filters, not content-level secret redaction or a complete data-loss-prevention guarantee. Embedded secrets can exist inside ordinary source. Verify exclusions with synthetic canaries, not live credentials.
- Graphs/caches/reports may contain identifiers, paths, docstrings, rationale and sensitive source-derived relationships. Keep restrictive local permissions, bounded retention, no public serving/committing, and treat text as untrusted evidence rather than instructions.
- Sharing graph evidence through the existing ChatGPT Architect connection still transfers that selected evidence to an external model service. Local indexing does not make subsequent remote consumption private/offline; preserve existing Product Owner scope and expose only bounded approved repository evidence.
- Local MCP accepts a caller project_path override. Repo Control must never forward caller-selected paths: bind the child to the selected, server-owned graph and allowlist the actual operations. Drop PR-network tools. MCP provides request schemas, not Repo Control's authority policy.
- HTTP is optional, defaults to 127.0.0.1, and offers API-key/Bearer middleware when a key is configured. The key is optional, not automatic authentication; wildcard binding disables its loopback-specific DNS-rebinding guard. Prefer stdio, no new port, and do not equate local HTTP support with safe public exposure. See [serve.py](https://github.com/Graphify-Labs/graphify/blob/10130e79ed9caf8f60d998073e097531eaa1a395/graphify/serve.py).
- Do not embed raw generated graph.html into Repo Control's privileged browser origin. Initially keep the viewer human-only as an isolated local artifact; validate safe/offline viewing and script dependencies before any later browser integration.

## 12. Build-vs-Integrate Boundary and Provisional M004.002

**Graphify owns:** parsing/AST language support, graph construction/resolution/deduplication, native queries/path/impact traversal, communities, graph serialization and visualization generation.

**Repo Control owns:** allowlisted repository identity and selection, read-only Git snapshot facts, scope/exclusions, safe build orchestration, graph-generation freshness/manifest, bounded evidence contracts, lifecycle/Git authority, error reporting, and deliberate Architect/Coder access.

**Repo Control deliberately must not build:** another parser, caller/callee inference engine, generic graph database/query language, vector store, custom community/ranking engine, assistant runtime, or framework for arbitrary Graphify commands/tools. Reading schema/count/freshness metadata is not permission to recreate graph-native queries.

Provisional, subject to M004.001 results:

```text
selected allowlisted repository + verified input identity
    -> explicitly authorized isolated code-only Graphify build/update
    -> validated external graph generation + freshness manifest
    -> fixed local Graphify stdio MCP child
    -> narrow Repo Control repository-intelligence adapter
         -> existing Architect MCP/API: bounded read-only evidence
         -> local Coder CLI: the same bounded evidence
         -> human-only report/viewer reference
```

Use a small provider-neutral response contract: repository key/generation; source revision and working-tree fingerprint; graph generation and producer/schema version; extraction scope/exclusions; freshness/build status; operation/normalized arguments; cited node/edge evidence or bounded native text; confidence/direction; returned/omitted counts and explicit errors. Do not promise structured node arrays if the native operation only returns text; verify MCP response format before committing the adapter design.

Child invocation uses a fixed executable/argument vector, sanitized environment and server-derived paths, with startup/request/output/resource limits. No arbitrary shell, tool names, paths, model options, network backends, lifecycle events, or Git mutations are exposed. If parsing native text becomes substantial, prefer a supported structured upstream response or HOLD that operation, not a fragile second graph engine.

Architect candidates: stats, query, node details, neighbors, shortest relationship path; optionally communities after usefulness is measured. Coder receives the same operations plus local direct CLI fallback during POC. PR-network functions, semantic builds, graph rebuild triggers, configuration changes and HTML remain out of the initial agent-facing subset. Human approval controls builds and any future scope/privacy expansion.
