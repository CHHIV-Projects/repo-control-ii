## 5. Chosen systemd Architecture

A system-level systemd unit is tracked at
`ops/systemd/repo-control.service`. It runs as `chuck`, starts at boot when
enabled, restarts after failure, and uses the project's `.venv` executable.
`NoNewPrivileges=true` and `PrivateTmp=true` are enabled; no filesystem
restrictions were added that could block normal Git operations.

One service process supports all configured repositories. The repository
registry is a human-readable TOML allowlist at `ops/repositories.toml`. The
configured default is Repo Control II; the current explicit entries also
include Vocab App. Both are validated from the server-side configuration, with
no filesystem discovery. The server process is not architected as a separate
instance per repository.

## 6. Service Unit Details

The unit specifies:

```text
User=chuck
WorkingDirectory=/home/chuck/projects/repo-control-ii
ExecStart=/home/chuck/projects/repo-control-ii/.venv/bin/repoctl web
  --repository-registry /home/chuck/projects/repo-control-ii/ops/repositories.toml
  --host 127.0.0.1 --port 8765
Restart=on-failure
RestartSec=3
NoNewPrivileges=true
PrivateTmp=true
WantedBy=multi-user.target
```

The service definition under version control is the source of truth; installation
copies that file to `/etc/systemd/system/repo-control.service`.

## 7. Process User / Permission Model

The service runs as `chuck`, not root. This preserves the Product Owner's
existing Git and filesystem authority. The repository registry path and every
configured repository are validated at startup. If a configured repository is
missing or invalid, startup fails instead of silently omitting it.

## 8. Loopback / Network Exposure Model

The application still rejects non-loopback binding. The service listens only
on `127.0.0.1:8765` on henderson-server1; Windows access is by SSH port
forwarding. No LAN/public binding, reverse proxy, external tunnel, or credential
store was introduced.

## 9. Windows Access Decision

The portable package is `ops/windows/RepoControlLauncher/`. The primary entry
point is `RepoControl.cmd`; its PowerShell helper supports browser launch and
`-TunnelOnly`. Optional scripts install and remove a per-user logon task. The
helper uses normal `ssh.exe` authentication for `chuck@henderson-server1`; it
does not embed credentials or change SSH host-key checking.

## 10. Windows Helper / Tunnel Behavior

The package:

1. `RepoControl.cmd` invokes `open-repo-control.ps1` for double-click use;
2. checks `http://127.0.0.1:8765/healthz`;
3. opens the browser if Repo Control is reachable, unless `-TunnelOnly` was
   requested;
4. fails clearly if local TCP port 8765 is occupied by a service that does not
   identify itself as Repo Control;
5. otherwise starts an SSH forward bound to Windows loopback, with
   `ExitOnForwardFailure` and keepalive options;
6. waits up to 20 seconds for the health endpoint; opens
   `http://127.0.0.1:8765/` unless `-TunnelOnly` was requested;
7. prints the tunnel process ID and a targeted `Stop-Process -Id <PID>` command.

Console-suppression correction: SSH is launched with `-WindowStyle Hidden`,
and the logon task now starts `wscript.exe //B //Nologo` with the portable
`start-tunnel-hidden.vbs` entry point. The wrapper creates PowerShell with
window style 0 (hidden), waits for completion, and propagates the helper's
exit code to Task Scheduler. PowerShell retains `-WindowStyle Hidden`. SSH stderr
is captured in a unique local log under
`%LOCALAPPDATA%\RepoControlLauncher`. Startup failures write
`last-failure.txt`, report an error for on-demand use, and exit with code 1
for Task Scheduler. The existing readiness timeout still stops only the
process started by the helper.

Hidden SSH uses `BatchMode=yes` and `ConnectTimeout=10` to avoid invisible
authentication/host-key prompts and bound connection startup. Normal OpenSSH
key/agent authentication and host-key verification remain in force. Initial
host-key acceptance and any password/passphrase interaction must be completed
in a normal terminal; no credentials or host-key exceptions are packaged.
The Product Owner confirmed the installed task now uses the `wscript.exe`
wrapper shown in the final Windows acceptance results in section 26. Re-run
the startup-task installer after replacing the package or changing its task
configuration.

The per-user startup-task installer invokes the helper with `-TunnelOnly` at
user logon. It updates only the same named task when its package-specific
description marker matches; the removal script checks that marker before
unregistering it. If SSH authentication or a first-time host-key prompt
prevents readiness, the helper reports the failure rather than weakening SSH
security.

## 17. Prepared-Action Restart Behavior

Focused tests prepared a commit, switched to another configured repository,
switched back, and verified the old confirmation could not execute. Repository
selection changes clear the in-memory prepared-action store. A selection
generation check rejects stale in-flight prepare/confirm requests, and a shared
lock serializes selection changes with Git confirmation execution. Service
restart creates a new in-memory store, likewise invalidating outstanding
confirmations. The Product Owner confirmed this behavior during operational
acceptance.

## 18. Supported Git Boundary

The initial R002 lifecycle remains:

```text
status / change and diff review
stage / unstage / restore selected paths
commit the complete explicitly staged set
history / commit detail / file history
local branch create / clean-tree switch / safe merged delete
fetch configured remote
non-force push / first publish with upstream
fast-forward-only update
```

Intentionally unsupported:

```text
merge / merge-conflict resolution
rebase / interactive rebase / cherry-pick
reset / stash / reflog recovery / worktrees / submodules
force push / force-with-lease / remote branch deletion
tag management / arbitrary refs or refspecs / general pull
history rewriting / GitHub PR or CI control / remote configuration editing
```

Manual Git remains the fallback for advanced cases.

## 19. Operator Workflow

The Product Owner opens the Windows helper, which reuses or starts the SSH
tunnel and launches the browser. The active repository name and absolute path
remain visible in the header. Where the registry contains multiple entries, a
CSRF-protected selector accepts only a configured repository key. It never
accepts a filesystem path from the browser.

The registry is read at service startup. Adding or changing entries requires a
service restart. Automatic filesystem discovery is not implemented.

## 20. Update / Restart Workflow

```text
Product Owner updates the repository and runs tests
review the resulting changes
sudo systemctl restart repo-control.service
verify systemctl status and the browser
```

There is no automatic pull/deploy hook, GitHub webhook, or restart-on-code-change
mechanism. Avoid simultaneous Git mutations through Repo Control and another
Git client or terminal.

## 21. Rollback Procedure

```bash
sudo systemctl stop repo-control.service
sudo systemctl disable repo-control.service
sudo rm /etc/systemd/system/repo-control.service
sudo systemctl daemon-reload
```

Rollback removes only the installed unit. It must not delete the repository,
`.venv`, Repo Control state, or Git configuration. The Windows tunnel can be
stopped with the PID printed by the helper; the helper file/shortcut can be
removed by the Product Owner if desired.

### Logon-window investigation

The Product Owner supplied the installed task action through a read-only
`Get-ScheduledTask` query:

```text
Execute: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
Arguments: -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File
  "C:\Users\chhen\RepoControlLauncher\open-repo-control.ps1" -TunnelOnly
WorkingDirectory: empty
```

This matches the previous tracked installer. It does not invoke
`RepoControl.cmd`, opens no browser, and the helper starts SSH hidden. However,
`powershell.exe` is a console executable: an argument handled inside
PowerShell is not a guarantee that its initial console creation is invisible.
Repo Control's direct task entry point therefore can produce an initial
flash. This identifies a plausible source, not proof that Repo Control caused
the observed 2–3-second window.

Bounded correction: only the automatic task entry point changes to the
non-console `wscript.exe` host and a small VBScript wrapper using
`WScript.Shell.Run(command, 0, True)`. The wrapper resolves the helper relative
to its own location, creates PowerShell hidden, and returns its exit code.
The accepted SSH helper, on-demand launcher, security options, diagnostics,
and task ownership/removal protections are unchanged.

## 30. Known Limitations

- A Windows-side copy of the portable launcher folder is needed to run it
  locally.
- PowerShell parsing and standalone Task Scheduler removal/negative-path tests
  were not run in the Linux coding environment or reported as separate manual
  acceptance items.
- Optional logon startup requires Windows Script Host/VBScript. VBScript is
  deprecated on newer Windows versions; the package does not install it or
  change policy. On-demand use remains independent of this wrapper.
- The active selection is shared by all browser clients and is in memory; a
  process restart returns to the configured default.
- Repository registry edits take effect after a service restart.
- The initial port 8765 listener was handled during Product Owner service
  installation; it is no longer a pending installation blocker.
