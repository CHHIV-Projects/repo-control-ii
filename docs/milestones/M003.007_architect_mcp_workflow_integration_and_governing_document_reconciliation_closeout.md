## 4. Architect MCP Workflow Integration

The persistent Secure MCP Tunnel is now the standard, established operational channel for Architect evidence retrieval:

```text
Product Owner & Architect (ChatGPT)
→ discuss milestone objectives and requirements
→ Architect queries Repo Control live via MCP tools:
  * repo_status / repo_review (active repo, selected milestone, phase)
  * repo_prompt (authoritative milestone prompt)
  * repo_document (governing context, architecture, workflow, rules)
→ Product Owner commits approved prompt and selects milestone in Repo Control UI (PLANNING)
→ Product Owner reviews and explicitly confirms transition: PLANNING → READY

Coder (VS Code)
→ inspects local repository and performs read-only Git preflight
→ Product Owner confirms transition: READY → IN_PROGRESS
→ implements approved scope, runs tests, creates closeout (no Git mutations)
→ Product Owner confirms transition: IN_PROGRESS → REVIEW

Architect (ChatGPT)
→ queries Repo Control live via MCP tools:
  * repo_review / repo_milestone / repo_workflow (review phase, events, binding lock-ins)
  * repo_closeout (review implementation report)
  * repo_git (inspect working tree cleanliness, modified/untracked files, HEAD)
  * repo_evidence (inspect reported test outcomes)
  * repo_document (verify governing document compliance)
→ evaluates implementation and advises Product Owner on acceptance

Product Owner
→ reviews Architect recommendation
→ performs guarded Git staging, commit, and push in Repo Control UI
→ records acceptance and closes milestone: REVIEW → CLOSED
```

## 5. Evidence Priority

When the Architect requires repository, milestone, or project evidence, the authoritative priority order is:

1. **Repo Control MCP Read-Only Tools** (`repo_status`, `repo_review`, `repo_milestone`, `repo_prompt`, `repo_workflow`, `repo_closeout`, `repo_git`, `repo_evidence`, `repo_document`): Current, deterministic state from the authoritative Linux host.
2. **Tracked Project Artifacts**: Authoritative Markdown files in the local repository (`docs/context/*`, `docs/milestones/*`).
3. **Current Git Evidence**: Deterministic branch, HEAD, commit history, and working-tree status.
4. **Product Owner Clarification**: Direct instruction from the Product Owner on goals, decisions, and priorities.
5. **Prior Chat / Memory**: Only consulted for conversational context when live evidence is unavailable. Never overrides deterministic facts.

The on-demand handoff packet generator implemented in M003.003 is retained as a permanent capability:

- **Architect Review Packets**: Maintained as an accepted operational fallback when the Secure MCP Tunnel is disconnected, degraded, or offline, or when an external reviewer requires a portable, self-contained Markdown export.

## 7. Milestone Selection Rule

Milestone selection follows strict explicit hygiene:

- The Product Owner must explicitly select the active milestone in the Repo Control browser UI.
- The active milestone is recorded in the external selection pointer (`.repo-control/selected-milestone.json`).
- Repo Control never infers or auto-selects milestones based on recent files, numeric order, or Git commits.
- MCP queries report the selected milestone; they cannot change selection.

---

## 8. Lifecycle / Git Separation

Repo Control enforces a strict boundary between workflow lifecycle and Git status:

- **Git is the version-control authority**: Tracks commit history, branches, working tree changes, and remotes.
- **Workflow sidecars are the lifecycle authority**: Track chronological event history, open conditions, binding lock-ins, and phase transitions.
- **Separate Operations**: Committing or pushing changes in Git does not automatically mark a milestone `CLOSED`. Creating a closeout file does not automatically advance a milestone to `REVIEW`. Transitions require explicit event recording by authorized actors.

## 12. Known Limitations

- **Read-Only MCP**: Architect MCP tools are strictly read-only GET requests; cannot mutate Git, files, selection, or lifecycle state.

- **Coder Integration**: Coding agents do not have direct MCP tool access; they consume local files or Coder Handoff Packets.
