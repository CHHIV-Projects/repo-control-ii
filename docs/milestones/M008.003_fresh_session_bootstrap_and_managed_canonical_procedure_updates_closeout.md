# Milestone M008.003 — Fresh-Session Bootstrap and Managed Canonical Procedure Updates

## 1. Scope Completed

- Added a read-only **Procedure Updates** browser page backed by the central repository registry and existing deterministic procedure status/preview APIs.
- Added per-managed-repository installed/target release, exact status, repository key/name/path, lock hash, overlay state, canonical manifest/source hashes, and bounded file diffs.
- Added strict allowlisted repository selection for previews. The target selector is independent from global browser repository selection; invalid, duplicate, blank, and unsupported query inputs fail closed.
- Added explicit error presentation with bounded details, a no-cache response, and a route for the linked operator guide.
- Added host-aware fresh-session guidance, a copy-ready proposed ChatGPT Architect project instruction, stable handoff phrase meanings, and start-to-finish generic procedure and independent governing-document maintenance guidance.
- Updated WORKFLOW-006 to reflect partial completion and preserved DOC-001 and unrelated deferred items.

## 2. Resulting Behavior

The browser navigation now includes **Procedure Updates**. Its GET page displays status for every configured managed repository. A **Review Update** link invokes only deterministic, read-only preview for that allowlisted key; preview output is bounded to 20,000 characters total and 4,000 characters per diff. The page displays exact current/expected hashes, action classifications, blockers, overlay status, and removal count. GET requests do not write files, change Git/lifecycle state, or switch the globally active repository.

The page and route expose no Apply/materialization action or endpoint. This is intentional: the existing materializer writes files one at a time and has no whole-update rollback/recovery. An internally unblocked preview is not permission to write.

Fresh-session guidance distinguishes host instruction loading from Repo Control behavior. Coder instructions direct users to the canonical local CLI from the intended worktree; the ChatGPT Architect snippet requires connected read-only tools and the currently selected repository, and explicitly forbids impersonating the Coder, guessing identity, or treating handoff phrases as authorization.
