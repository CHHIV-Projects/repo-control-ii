## Phase B — v2 storage and independent integrity primitives
4. Implement strict v1/v2 dispatch. Preserve v1 parser, marker, event objects, caps and semantics; NEVER interpret unknown, partial or incompatible v2 as a valid empty or truncated v1 ledger. Keep the canonical <stem>_workflow.md as the sole v2 authority anchor. Its bounded manifest (target <=256 KiB) binds schema version, repository ID, milestone ID, prompt path AND SHA-256, generation/transaction ID, exact event count/last sequence/event ID, segment catalog and projection roots, and derived lifecycle checkpoint. V1 remains byte-for-byte unchanged until explicitly authorized migration in a disposable fixture.
5. Immutable segments preserve the exact original event fields/IDs/order/timestamps, consecutive global sequence numbers and repository/milestone/prompt identity. Target <=64 events and <=256 KiB per segment; validate predecessor digest, event count/length, segment metadata and full chain. Create bounded content-addressed copy-on-write segment-catalog and projection indexes (target <=64 KiB per B+ tree page); immutable pages are rooted and hashed by the manifest. The fixed anchor must not grow with the number of unresolved questions, classified bugs or historical decisions, and no silent total-event cap or index truncation is permitted.
6. Implement the complete M009.021.001 transition projection, preserving all 21 event-type constraints and historical reference relationships: unanswered questions, classified/unfixed bug IDs, current WAITING boundary and later qualifying resolution, Product Owner bindings/decisions, closeout reference, acceptance-before-closure adjacency, reopen/correction and verification expectations. Use verified bounded index paths for normal appends (target approximately O(log N) per relevant lookup/update) rather than replaying every prior event. A complete audit remains O(history). Hash proofs support consistency only, not authenticated actor identity or adversarial tamper-proof storage.
7. Single commit protocol under M009.021.002 state-root lock: validate current identity/expected generation, write and fsync immutable segment and index/catalog pages and containing directories, then write/fsync a new bounded anchor, atomically replace it and fsync anchor directory. That successful durable anchor is the commit point. Stable transaction/event IDs must support uncertain acknowledgement reconciliation without false success or duplicate append. Never overwrite an existing committed segment; preserve/report orphans and incomplete temporaries, block writes on unresolved corruption or unsafe recovery. Fail closed on bad/missing/mismatched/tampered pages, path traversal or symlink, unexpected identity, disk-full, permissions, fsync or replace failure and obsolete-version clients.
8. Migration is FIXTURE ONLY. Fully validate v1, retain source v1 image/digest, preserve original event IDs and payloads, write and verify v2 segments/indexes, replace anchor last. A precommit failure leaves v1 authority intact; an uncertain postcommit outcome requires validation/reconciliation. A v2 history beyond v1 limits cannot silently roll back to a truncated v1 representation; use documented forward repair or a compatible v2 reader. Do not migrate the selected M009.021.003 sidecar or historical real milestones.
