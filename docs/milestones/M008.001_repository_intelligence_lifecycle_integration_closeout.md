# Milestone M008.001 — Repository Intelligence Lifecycle Integration

## 1. Scope Completed

- Integrated a Repository Intelligence baseline with Product Owner `Approve & Start` and legacy `READY → IN_PROGRESS` starts.
- Added the bounded `repoctl coder-intelligence-refresh` operation and guarded service endpoint for authorized Coder refreshes.
- Removed the separate approval checkbox from the manual Intelligence Value graph action and separated bounded refresh receipts from evidence-query measurements.
- Updated Repo Control II documentation and released the shared procedure at version `1.1.0`.

## 2. Resulting Behavior

- Start checks freshness before changing lifecycle. A CURRENT graph is a no-op; a supported MISSING/STALE graph is rebuilt and verified against the same source identity. A failed or non-CURRENT required build does not write start events. Unsupported source scope reports `NOT_AVAILABLE` and preserves normal lifecycle behavior.
- Before start events are written, repository selection/generation, selected milestone and prompt identity, phase, event count, and graph freshness are revalidated. Publication rechecks authorization while holding the state artifact lock; graph extraction does not hold that lifecycle artifact lock.
- `coder-intelligence-refresh` has no repository, path, provider, scope, or build options. It resolves the managed workspace from the central registry, checks `IN_PROGRESS` authorization and waiting conditions, and requires the service-selected repository to match. The endpoint revalidates milestone, prompt, event history, repository generation, and authorization at publication. CURRENT is a no-op; refreshes affect only existing external derived graph state.
- The manual Build / Refresh button remains protected by CSRF and selected-repository/generation validation; the redundant checkbox is removed. SQLite refresh receipts use a separate bounded table, retain only bounded provenance/hashes/error codes, and do not count as evidence queries or ratings.
- Prompt content SHA-256 identity is carried through workflow forms and Coder status to reject stale prompt submissions.
