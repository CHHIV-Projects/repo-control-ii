## 2. Resulting Behavior

- `python -m repoctl.backup backup` takes a consistent local SQLite snapshot, validates identity, schema, selection, workflow history/projection, document hashes, integrity and foreign keys, then verifies the destination bytes and snapshot before publishing a manifest.
- Transfers use unique partial files and preserve earlier verified copies after interruption or verification failure.
- `python -m repoctl.backup restore` verifies the manifest and creates a new file under the separate restore directory; it refuses overwrite and enforces that the CLI restore target is outside the NAS mount and on a different filesystem.
- `python -m repoctl.backup monitor` checks the mounted share identity and newest verified-copy age, and invokes only a configured absolute executable alert hook.
- The proposed backup timer is scheduled at minutes 00, 15, 30 and 45; the independent monitor timer is scheduled every five minutes and uses the 20-minute freshness threshold.
- All backup, restore, monitor, and application integration tests used temporary disposable stores. No production timer or alert route was activated.
