## 6. Minimal Shared Initialization Contract and Threat Model

Reuse `coder-context` as the authority source. A thin adapter should validate
successful CLI exit and JSON shape, then present:

- managed repository key, repository ID, canonical worktree path;
- selected milestone ID, prompt path and existing prompt SHA-256 identity;
- lifecycle, authorization status, correction scope and explicit stop state;
- latest binding lock-in, applicable approved dispatches, open questions/bugs,
  and the required governing-document references;
- observation time, CLI exit/result, and optional branch/HEAD as diagnostic
  worktree facts, not additional authority.

On CLI failure, malformed data, absent/invalid selection, unmanaged path, or
identity mismatch, return an explicit **invalid/no-authority** result and do
not manufacture a success-shaped fallback. The adapter must not silently
cache lifecycle authorization. A repository-registry generation is not
currently exposed; if a future design truly needs it, it must be additive
metadata from the authoritative registry, not a parallel selection source.
Branch/HEAD and an observation timestamp are also absent today.

Inject the verified current prompt and a concise authority/status header at
startup/resume; do not inject whole source trees, all history, or prior
transcripts. Keep the current event summary and approved bindings; fetch
governing documents, code, tests, and structural/history evidence on demand.
The current full context is 23,032 JSON bytes, while the active prompt alone
is 19,461 bytes. Codex's documented context threshold makes output sizing and
effective delivery a required host test, not an assumed token conversion.

**Authorization and threats are separate from initialization:**

- A stale session, lifecycle change, compaction, or milestone handoff can make
  injected status obsolete. Re-resolve before consequential operations.
- Wrong worktree, symlink/registry mismatch, missing CLI, bad JSON, or hook
  timeout must not convey authority. Current CLI resolution fails closed on
  unmanaged/invalid identity, but does not return a structured invalid
  context object.
- Repo/user hook configuration can execute commands with the runtime host's
  permissions. Review/trust sources, pin dependencies, use the worktree root,
  avoid network services, and never log raw prompts, dispatch bodies, tokens,
  or tool arguments.
- Copilot documents that `preToolUse` timeout can fall through to normal
  permissions. Codex documents that `PreToolUse` errors, timeouts, or
  malformed responses may fail without blocking; some specialized/hosted tool
  paths are not covered. A supported explicit denial is a guardrail, not a
  complete compliance boundary.
- Repo Control lifecycle APIs protect Repo Control operations, not arbitrary
  editor/shell writes. Use Product Owner-controlled host permissions,
  sandboxing, and Git credentials for consequential-action controls. Never
  describe instructions, context, or a fall-through-prone hook as a
  fail-closed authorization grant. Product Owner retains all Git mutation
  authority.
