## 5. Adapter contract and boundaries

The adapter produces the documented Codex-shaped
`hookSpecificOutput.hookEventName = "SessionStart"` and
`hookSpecificOutput.additionalContext` shape in fixtures and CLI smoke tests.
The inner payload uses `repo-control.continuity.v1`, live canonical repository
identity, milestone/prompt path and hash, lifecycle/authorization, applicable
scope references and explicit stop instructions. Context is bounded to 8,192
UTF-8 bytes; the reported 585-token estimate uses `ceil(bytes / 4)` and is a
heuristic, not model tokenizer telemetry.

The previous direct canonical CLI/adapter smoke recorded in test event
`0a11d271c0484ee391fadefa99109eb3` reported 2,338 UTF-8 bytes / 585 estimated
tokens, with canonical CLI exit 0 for M009.003 `IN_PROGRESS`. It used a
simulated Codex event and no marker or receipt. This is adapter/CLI smoke only.

Neither the adapter nor additional context is a tool/file permission boundary.
If the host does not discover, trust or invoke a hook, or does not consume its
context before responding, the adapter cannot enforce a stop. No claim is made
of fail-closed authorization, actual host execution, or pre-first-response
delivery.

## 8. Deviations, limitations and follow-up

Approved A3 reduced the original acceptance goal after two bounded
investigations and repeated UI refreshes did not reveal a repo hook or normal
repo-scoped trust path. This closeout therefore records a **bounded
compatibility/design finding with experimental adapter artifacts**, not an
implementation PASS for the original two-host automatic-bootstrap objective.

Still **NOT VERIFIED**:

- Whether the selected VS Code Codex runtime can load project hooks when
  configured/trusted through a supported flow.
- Hook discovery, per-hook trust, command execution in the intended worktree,
  and model consumption before the first substantive reply.
- Codex event delivery for startup, resume, compact, clear or fork in this
  selected UI.
- Effective Windows-client build, policy and trust state.
- Genuine Copilot resume/reopen behavior, which remains a separate unresolved
  M009.002 dependency; the Copilot fixture regression does not resolve it.

Recommended follow-up is a new Product Owner-approved milestone only after a
supported, safe, repository-scoped hook discovery/trust path is available in
the exact VS Code Codex host. Any alternate Codex host, explicit operator
bootstrap, or cross-repository rollout requires a separate scope decision.
Cross-agent Copilot ↔ Codex session-switch acceptance remains future work; it
must preserve the same managed repository and selected milestone. Do not copy
or install the illustrative hook in another repository.
