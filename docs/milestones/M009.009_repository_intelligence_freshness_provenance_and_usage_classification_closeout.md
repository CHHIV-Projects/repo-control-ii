## 2. Resulting Behavior

The semantic identity is a deterministic hash of the supported-source content hash, the versioned source/options configuration, producer version, graph schema, and semantic-identity schema. Source file metadata and content hashes are checked before comparing that identity with a fresh source snapshot. Repository ID and resolved repository root are separate compatibility boundaries.

Git HEAD and branch remain factual build provenance. Changes to HEAD or branch alone no longer stale a graph whose semantic inputs are identical; status reports those provenance changes separately. Changed supported-source inputs produce `STALE`. Missing, malformed, legacy, or mismatched identity and production metadata fail closed as `INCOMPATIBLE`. Repositories with no supported source files report `NOT_AVAILABLE`. Refresh receipts use semantic identity and remain separate from structural query uses.

The existing graph predates the new identity and requires a deliberate rebuild before it can serve as current evidence. Queries do not rebuild implicitly.
