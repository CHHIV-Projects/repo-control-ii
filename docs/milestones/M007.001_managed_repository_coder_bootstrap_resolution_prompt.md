# M007.001 — Managed-Repository Coder Bootstrap Resolution

## 1. Objective

Implement the first milestone of the M007 managed-context integration arc by resolving `INTEGRATION-001 — Managed-Repository Coder CLI Resolution`.

A fresh or resumed co-located Coder working in any centrally managed repository must deterministically resolve the **same managed repository identity and configuration** that the Repo Control browser and Architect use.

The implementation must eliminate the current unsafe/ambiguous behavior where direct Coder CLI operation can silently fall back to a synthetic `default` repository configuration when the managed repository cannot be proven.

This milestone does **not** implement Architect document/history retrieval (`INTEGRATION-002` / `INTEGRATION-003`) and does not introduce a Coder MCP.

---

## 2. Accepted M007.000 findings to preserve

M007.000 established that:

- browser/Architect repository identity comes from the centrally configured Repo Control registry;
- direct `coder-context` / `coder-status` currently derive repository path from `--repository` or cwd;
- Coder resolution currently looks for `ops/repositories.toml` inside the selected repository;
- read/parse/validation failure can fall through to a synthetic `default` config using default milestone/document paths;
- Vocab App reproduced this mismatch: path/selection happened to resolve, but repository key became `default`;
- the effective `repoctl` executable is determined by the caller/module/PATH and no current Coder path locates a canonical executable;
- no evidence showed that a Coder MCP is required.

Treat those findings as the implementation baseline unless current source has materially changed. If implementation reality contradicts them, stop and report the evidence before broadening scope.

---

## 3. Product Owner intent

The normal Product Owner handoff should remain minimal:

```text
Prompt ready.
Correction ready.
Instruction ready.
```

Those messages are only human signals. They do not carry repository identity or authorization.

The Coder bootstrap must be able to determine, from deterministic Repo Control configuration/state:

```text
managed repository key
repository path
configured milestone root
selected milestone
lifecycle/authorization
applicable approved Architect dispatches
governing-document references
```

A fresh Coder session must not need:
- prior chat history;
- copied milestone summaries;
- per-project Repo Control installation;
- manually supplied `--milestone-root` in the normal managed-repository case;
- a project-local copy of the central registry;
- a silent `default` fallback.

# PART B — CANONICAL MANAGED-REPOSITORY RESOLUTION

## 5. Use the central managed-repository configuration

Refactor Coder repository resolution so managed-repository lookup uses the same authoritative central repository configuration used by the browser/Architect rather than expecting each managed repository to contain its own `ops/repositories.toml`.

The implementation should reuse existing registry/configuration parsing where practical instead of creating a parallel configuration format.

The source of configuration must be explicit and testable.

## 6. Resolution contract

For normal co-located use:

- If `--repository` is supplied:
  - canonicalize/validate it;
  - require it to map to exactly one centrally configured managed repository;
  - return that managed repository's actual key, path, configured milestone root, and document mappings.

- If `--repository` is omitted:
  - derive the candidate repository from cwd as today;
  - canonicalize it;
  - require it to map to exactly one centrally configured managed repository.

- If the candidate maps to zero managed repositories:
  - fail clearly;
  - do **not** silently create/use key `default`.

- If the candidate maps ambiguously to more than one managed repository:
  - fail clearly;
  - do not guess.

- If the central registry/config cannot be read or validated:
  - fail clearly for managed-repository bootstrap;
  - do not synthesize a managed identity from defaults.

An explicit repository path is a disambiguation input, not permission to bypass central registry validation.

## 7. Preserve repository-scoped state identity

After managed repository resolution, preserve the existing repository-scoped state model:

- repository ID must remain consistent with Repo Control's accepted identity scheme;
- external selection pointer must remain scoped to that repository ID;
- configured milestone root must come from the managed repository entry;
- selected milestone/lifecycle must be resolved from the authoritative state root;
- applicable approved Architect dispatches must remain milestone/repository scoped;
- governing-document references must come from the managed configuration.

Do not merge repository selection state across projects.

# PART C — CANONICAL CODER ENTRYPOINT / EXECUTABLE

## 8. Resolve the executable/bootstrap concern

M007.000 found that no current Coder path selects a canonical `repoctl` executable and that shell PATH can determine which installation runs.

Implement the smallest safe mechanism needed so documented/normal Coder startup uses the authoritative Repo Control II installation rather than an arbitrary legacy/project-local executable.

Evaluate and implement the least-complex accepted approach. It may be documentation/bootstrap based if that is sufficient, or a stable wrapper/entrypoint if code is required.

Requirements:

- normal VS Code Remote SSH Coder workflow must have one documented authoritative invocation;
- no project-local Repo Control installation is required for managed repositories;
- do not depend on PATH accidentally resolving the desired install;
- stale/legacy executable ambiguity must be detectable or avoidable;
- the approach must remain workable from Repo Control II and Vocab App worktrees;
- do not introduce a daemon, network transport, or Coder MCP merely for executable selection.

If source evidence shows the executable concern cannot be safely solved within this milestone without a host-level install/configuration decision, stop and escalate with the smallest options rather than silently broadening scope.

- canonical repository path;
- repository ID;
- configured milestone root;
- selected milestone;

- registry unavailable;
- registry invalid;
- duplicate/ambiguous managed mapping;

- configured milestone root invalid/missing;
- selected milestone missing/invalid;
- state-root problem.

Do not expose secret values or dump raw configuration unnecessarily.
