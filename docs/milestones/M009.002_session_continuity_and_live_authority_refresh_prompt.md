## 2. Objective and acceptance boundary

Deliver a documented, testable **continuity and live-authority-refresh contract** reusable by future Copilot, Codex and local-agent adapters, plus the smallest safe modification to the current Copilot integration needed **if supported by the observed installed host**.

At minimum the contract must answer:

1. What constitutes a genuine fresh session, resumed session, reopened transcript/checkpoint, compaction, subagent start, later user-turn handoff, and work-authorizing transition **in the installed host**?
2. Which events are host-observable and capable of delivering new initialization context before subsequent substantive work? Which are merely UI or model-reported phenomena?
3. When must the Coder re-query canonical Repo Control identity/lifecycle/open conditions/approved scope rather than reuse a prior context snapshot?
4. How are `AUTHORIZED`, `NO_AUTHORITY`, `INVALID_NO_AUTHORITY`, timeout, and not-verifiably-fresh results represented without implying permission?
5. What, if anything, is enforced by the host, and which safeguards remain **Coder procedure only**?

**Do not pretend** that a model instruction, startup hook, optional status query, or stale status warning itself creates a fail-closed file/tool enforcement boundary. If the host cannot guarantee authority refresh at a particular trigger, preserve the limitation and report a bounded Product Owner decision instead of claiming a complete solution.

## 4. Gate B — Minimal continuity contract and narrowly justified implementation

After Gate A confirms a supported path and live `IN_PROGRESS` authority, implement only the smallest defensible delta.

- Retain `coder-context` and Repo Control as the **single authority** for repository selection, lifecycle, prompt identity and approved decisions. Do not build a parallel registry, session authority cache, event ledger, service or network-facing agent gateway.
- Establish a **versioned, agent-neutral continuity envelope/contract** (e.g. documented schema/fixture tests over existing compact context), explicitly identifying current repository key/id/path, selected milestone/prompt path+hash, lifecycle/authorization, open blockers, approved-scope references, observation/freshness provenance and stale/invalid/no-authority handling. Use actual existing CLI fields; do not invent missing authority. Do not inject full prompt or dispatch bodies by default.
- Where the installed Copilot hook supports a genuine resumed-session callback, reuse the existing read-only adapter and canonical CLI; ensure a fresh lookup on each observed invocation, no cached "authorized" fallback, and correct `source=resume` mapping. Distinguish missing callback from a successful refresh.
- Provide a **bounded, read-only on-demand refresh procedure** for work resuming in a chat where no supported host event is proven. Before implementation or other consequential work, obtain current `coder-context` in the exact worktree; if it fails, mismatches, or reports WAITING/REVIEW/CLOSED, **STOP** and escalate through Repo Control. Such a procedure is not guaranteed host enforcement. Avoid a "prompt ready" requirement that makes fresh automatic startup depend on the model voluntarily calling a tool.
- Change only the existing repo-scoped adapter/config and narrowly necessary tests/docs **when real host evidence justifies it**. If no code change is needed, evidence and deterministic tests/documentation can be the authorized output; do not code merely to fill a milestone. Preserve normal fresh-session acceptance and all hard stop/no-authority semantics.
- Keep output bounded, valid for the actual host channel, with mandatory identity/lifecycle/invalid fields never truncated. Diagnostics must be temporary/opt-in, non-sensitive, and disabled at closeout. No secret logging, full prompts, shell interpolation, unsafe `cwd` trust, or writes to another repo.
- Separate **host context delivery**, **Coder decision/refresh guidance**, **Repo Control workflow authorization**, and **actual host tool/file permission enforcement** in both implementation and closeout. A `preToolUse`-style guard with uncovered tools or fail-open timeouts cannot be reported as universally fail-closed.

If an on-resume hook, additional context-delivery event, CLI extension, shared-procedure release change, enterprise/user hook, permission/sandbox change, or cross-host integration requires unapproved scope, **STOP** and raise a targeted question before making it.

## 5. Gate C — Controlled validation and real continuity evidence

Use deterministic fixtures for negative cases and **the actual approved Copilot runtime** for host-delivery claims.

Minimum evidence table with PASS/FAIL/NOT VERIFIED/NOT SUPPORTED and source:

1. **Fresh-session regression:** new chat, exact `Prompt ready.` with no attachment; real host hook invocation, CLI exit/worktree/identity/lifecycle, bounded `additionalContext`, and first-response delivery independently correlated. No manual milestone prompt or text file attachment required.
2. **Genuine resume:** if the installed host supports `source=resume`, invoke that **actual** route through a documented, reproducible procedure; match host receipt (new observation, fresh CLI call and real state) with model-facing output. A "Checkpoint Restored" banner alone is NOT PASS. If no reproducible route exists, record **NOT VERIFIED** and escalate to the Product Owner before overall continuity acceptance.
3. **Restore without callback:** reopen a transcript/checkpoint in a scenario with no actual hook trace; prove the documented fail-safe **operator/Coder behavior** requires live recheck before consequential action; do not assert automatic refresh or comprehensive prevention unless directly enforced by the runtime.
4. **Stale authorization:** in isolated nonproduction fixtures, simulate IN_PROGRESS becoming WAITING/REVIEW/CLOSED after the initial snapshot, a different managed repository/worktree, changed milestone/prompt identity, and an absent/invalid selected milestone. A newly fetched live result must supersede cached context; never produce success-shaped authorization for a bad or stale condition. Do not modify the real active Repo Control lifecycle just to test a stale transition.
5. **Fault injection:** missing CLI, malformed/noisy output, nonzero exit, timeout, oversized response, symlinks/relative `cwd`, and unsupported lifecycle. Verify clear `NO_AUTHORITY`/invalid responses without prior-success fallback. Document observed host-level tool permissions/fail-open gaps separately.
6. **Secondary paths:** compaction, subagent, and a different model if genuinely supported without global configuration changes; document unsupported or unobserved paths, do not invent PASS.
7. **Security/property preservation:** no Git mutations; no Repo Control selection or lifecycle writes by the adapter; no changes to trust, sandbox, permission prompts, global/user hook locations or other managed repositories. Tests and receipts are read-only to production state, with opt-in bounded metadata logs cleaned up after acceptance.
8. **Efficiency:** measure emitted envelope in UTF-8 bytes and explicitly named estimated evidence token formula/version, not an unqualified tokenizer count. Compare to the 2,413-byte/604 estimated-token M009.001 historical sample when meaningful; do not conflate this heuristic with true model token use.

For real-host tests, a model stating "I refreshed" is NOT independent evidence. Use a protected short-lived receipt tied to actual command invocation/exit, a distinct non-sensitive marker injected by the hook, and first-response correlation where the host supports it. Do not preserve probe markers in production.

**Overall result:** The **continuity host-backed claim** is PASS only for event paths actually observed and proven. If genuine resume cannot be exercised, a product-owner-approved **re-scope or explicit limitation decision** is required; fresh-session regression PASS alone is not sufficient to claim resumed-session automation. Do not silently repeat the M009.001 "NOT VERIFIED" exception as a successful new solution.

## 6. Security and architectural boundaries

Repo Control remains source of truth and PO owns approvals. Coding agents remain read-only for Git; host hook and CLI refresh never stage/commit/push/tag or change selected repository/workflow phase. No model self-authorization. When WAITING, Coder may perform only approved bounded diagnosis or escalations; no implementation. The installed host's already-permissive settings must not be weakened, and this milestone does not authorize changing them.

Avoid a new agent framework, new MCP server/service, headless client broker, shared hook installation, persistent shadow auth state, agent-specific prompt duplication, or embedding prompt bodies into startup context. Keep the design portable to later Codex and local agents through an authority contract, not by assuming their hook event names or permission semantics match Copilot.

**Do not release or regenerate shared/procedure or silently propagate to Vocab App / Photo Organizer / other managed repositories.** Future onboarding requires independent, approved host/repo evidence.

## PASS criteria

- Current managed repo, milestone and lifecycle safely verified; no unauthorized edits or Git mutations.
- A concrete, documented provider-neutral **continuity and live-authority-refresh contract** grounded in canonical Repo Control state.
- Deterministic validation proves stale or invalid authorization is never represented by the refresh mechanism as current authorization.
- The supported actual Copilot host paths are observed and accurately classified; any claimed automatic resume refresh is independently proven **on a genuine resume**, not inferred from checkpoint restore or chat testimony.
- Fresh-session behavior from M009.001 is preserved, with mandatory fields and error states intact.
- Acceptance evidence, operator procedure, limitations, rollback instructions, tests and truthful closeout are complete.

**NOT PASS:** cold-start alone used to claim resume safety; a model saying it rechecked without CLI trace; calling `Checkpoint Restored` an SDK `source=resume` without event evidence; reused cached lifecycle as standing permission; an unapproved Codex adapter; host security behavior described as universally fail-closed without coverage proof.

**Intended end state:** a trustworthy, reusable continuity contract plus a verified or transparently bounded first-host refresh mechanism, establishing the foundation for a later Codex adapter and eventually multi-repository agent portability.
