## 2. Resulting Behavior

The scanner previously passed `os.dup(directory_fd)` to `os.scandir`. Closing
the scandir iterator does not close a caller-supplied descriptor, leaving the
duplicate unowned and open for every visited directory. The descriptor was
also leaked if scandir failed after the duplicate was created.

The scanner now passes its already-owned `directory_fd` directly to
`os.scandir`. It keeps that descriptor open while sorting and inspecting the
resulting `DirEntry` objects, then closes it in `finally`. Normal completion,
scan errors, and bounded early returns all close the descriptor. Historical
root policy, descriptor-relative traversal, no-follow protections, limits,
result ordering, classification, and API error contracts are unchanged.

An isolated pre-fix fixture returned HTTP 200 for 25 nested searches while
open descriptors grew from 9 to 184 (+175). The same post-fix reproducer
returned HTTP 200 for all 25 searches with counts of 9 before and 9 after
(delta 0).
