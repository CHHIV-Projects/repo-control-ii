## 2. Resulting Behavior

The Copilot adapter now rejects a canonical payload that reports
`authorized=true` while its milestone phase is not `IN_PROGRESS`, returning
`INVALID_NO_AUTHORITY` rather than success-shaped authorization. Each observed
hook call still invokes the canonical `coder-context` CLI; the tests show a
subsequent live non-authorizing result replaces the preceding authorized
fixture response without a cache.

The new guide directs a Coder returning to consequential work to query current
Repo Control context in the exact worktree and stop on unavailable, mismatched,
invalid, or non-authorizing state. This is procedural guidance, not host-level
tool/file enforcement.

No host configuration or permission setting changed, so no operational
rollback is needed. The only production-code delta is the lifecycle coherence
check; any later removal remains subject to Product Owner review and the
separate Git-owner process.

identity, selection, prompt identity, workflow lifecycle, open conditions, and
approved scope. The guide defines `repo-control.continuity.v1` as an
agent-neutral interpretation of existing canonical fields, not a new CLI
format, registry, persisted authorization record, or independent lifecycle.

Repository Intelligence was **NOT USED**: its previously observed status was
CURRENT, but this was a localized adapter predicate and its directly related
fixture suite; structural relationship evidence was not materially useful.

required refreshed evidence. Direct source, fixture, and runtime output remain
the evidence for behavior; no graph receipt or query informed implementation.
