## Background and observed defect

The existing Repo Control Coder bootstrap is generated from a versioned shared procedure and instructs a coding agent to run:

```bash
/home/chuck/projects/repo-control-ii/.venv/bin/python -m repoctl.cli coder-context
```

The Product Owner expects a **fresh Copilot or Codex session** to recover authoritative Repo Control context from a minimal handoff, without previous chat history or manually supplied milestone prompts. The current failure report is narrower and concrete:

- Fresh GitHub Copilot sessions in both Vocab App and Repo Control II responded to `prompt ready` by asking the user for a task, rather than invoking `coder-context`.
- Copilot's `/env` listed `.github/copilot-instructions.md` under Custom Instructions and discovered Repo Control Skills, but this did **not** prove the bootstrap text was delivered in the first outbound model request.
- The recorded Copilot sessions used a VS Code Copilot SDK/`copilotcli` agent host; neither attempted `coder-context`. The available logs did not capture a complete first model request. A built-in `sessionStart` callback did not itself provide Repo Control initialization context; no Repo Control hook was registered.
- When explicitly instructed to retrieve Repo Control context, Copilot could return the correct repository, milestone, lifecycle, and absence of implementation authorization.
- At least one apparent earlier successful bootstrap was reported; there is not yet a comparably instrumented, verified successful baseline. A host/runtime regression remains a **hypothesis**, not established cause.
- The shared Copilot bootstrap's operative text was unchanged across procedure releases 1.0.1, 1.0.2 and 1.1.0; do not attribute the failure to those releases without evidence.

These are investigation leads drawn from Product Owner diagnostics, not substitutes for live verification. Preserve the distinction between **file discovery**, **instruction delivery**, **model compliance**, and **actual tool execution**.

## Architectural invariants (must preserve)

1. **Repo Control owns authority.** The live managed repository, selected milestone, lifecycle, active prompt, approved decisions, questions, and evidence are not inferred from chats or local filenames.
2. **One agent-neutral Coder contract.** Copilot, Codex, and eventual local coding agents are interchangeable *clients* of the same Repo Control workflow. Agent-host-specific adapters should remain thin.
3. **No history dependency.** A brand-new Coder session must orient from durable Repo Control/repository state; past conversation is useful but non-authoritative and must not carry unique required decisions.
4. **Authorization is separate from context.** Retrieval and injection of current information do not automatically authorize implementation. Respect `IN_PROGRESS`, correction-only scope, `WAITING`, `REVIEW`, `CLOSED`, and other state boundaries.
5. **No Coder Git mutations.** No stage, commit, push, tag, merge, rebase, reset, stash, clean, branch switch/create/delete, or remote mutation. Product Owner exclusively controls Git.
6. **Fail safely, with tested limits.** Do not assert that a nonblocking or timeout-prone agent hook enforces authorization. Document which execution boundaries can actually deny writes or tool use and how failures are handled.
7. **Versioned shared distribution.** Accepted shared procedures/adapters should eventually propagate through Repo Control Procedure Updates, preserving repository-specific overlays and independent Product Owner approvals.
8. **No unnecessary orchestration framework.** Reuse `coder-context`, Coder event operations, canonical governing docs, shared workflow/Skills, and existing lifecycle machinery rather than rebuilding these services.
9. **Portable handoff during a milestone.** Eventually an agent must be able to recover committed/uncommitted work, recorded tests and decisions, open blockers, and remaining authorized scope without importing another agent's transcript. This milestone **evaluates** that requirement; it does not implement it.

## D. Evaluate deterministic bootstrap and enforcement designs

Compare at least the following options without implementing them:

- Copilot `sessionStart` command hook using the existing `coder-context`, with validated, bounded `additionalContext` output.
- Host-level initialization/adapter that executes `coder-context` *before* the first model response when available.
- Codex-specific supported hook/entrypoint mechanism (not a copied Copilot configuration).
- Instruction-only fallback, explicitly marked **insufficient as the sole guarantee** when the host skips the retrieval command.

For each option assess integration complexity, runtime dependencies, version compatibility, context/token cost, observability, model independence, wrong-repository behavior, refresh-on-resume and later handoff, and failure-mode safety.

Define the **mandatory authorization boundary** independently of context injection. Evaluate pre-tool guards or another supported tool-level gate for consequential writes/commands; identify any allowed timeout/error fall-through. If no reliable gate exists in a given host, state its limitation and recommend Product Owner-controlled permissions/sandbox restrictions rather than claiming fail-closed enforcement.

A startup hook must retrieve actual context rather than merely ask the model to run the retrieval command. Do not store mutable lifecycle status as a permanent unrefreshed authorization grant.
