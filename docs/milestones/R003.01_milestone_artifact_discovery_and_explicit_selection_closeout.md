## 2. Final Discovery Contract

### Configured milestone root

- Each repository has exactly one server-controlled, repository-relative
  `milestone_root`.
- The root is read from `[repositories.<key>]` in `ops/repositories.toml`;
  the browser cannot provide or override it.
- The current configuration is:

  ```toml
  [repositories.repo-control-ii]
  milestone_root = "docs/milestones"

  [repositories.vocab-app]
  milestone_root = "milestones"
  ```

- Existing registry entries that omit `milestone_root` retain compatibility
  through the `docs/milestones` default. Single-repository mode uses the same
  default.
- Registry validation rejects absolute paths, empty/dot/traversal components,
  backslashes, and roots containing symlinked path components. Discovery is
  restricted to this root; it does not scan the repository generally.
- Discovery recurses beneath the configured root. Folder names do not
  contribute to process type, identity, artifact type, or workflow state.
  Symlink directories are not traversed, and artifact symlinks are not
  selectable.

### Canonical forward-looking filenames

```text
<process_code><arc_id>.<sequence>[.<subsequence>...]_<name>_<artifact_type>.md
```

- The only supported canonical process code is `M`, meaning Milestone.
- Every numeric component is exactly three ASCII digits. The arc and sequence
  are required; one or more three-digit subsequence components are optional.
  Examples: `M003.001`, `M003.010`, `M003.010.001`.
- `<name>` is a lowercase ASCII snake_case slug with nonempty components.
- The only recognized artifact types are `prompt` and `closeout`.
- Numeric hierarchy is parsed numerically. Candidates sort descending within
  process-code groups, with deeper identifiers before their parent when the
  parent components are equal. Process codes are grouped deterministically;
  currently `M` precedes the temporary legacy `R` group. Sorting never
  selects a candidate.

### Pairing, invalid artifacts, and ambiguity

- Prompt and closeout pair by identical canonical milestone ID and slug; their
  paths may be in different subfolders.
- A closeout is reported present only when exactly one valid closeout matches.
  Multiple closeouts for one ID are surfaced as ambiguous and are not reported
  as present. Unmatched closeouts are warnings.
- More than one valid prompt with the same milestone ID makes that ID
  ambiguous and all such prompts are excluded from selection.
- Malformed prompt/closeout-like filenames and unknown process/artifact types
  are reported as warnings rather than coerced into candidates.
- Paths are resolved and constrained beneath both the repository and its
  configured milestone root. Browser selection submits only an ID; the server
  resolves it against a fresh inventory before writing the pointer.

## 3. Historical Compatibility

No historical artifact was renamed, moved, or rewritten. A narrow compatibility
grammar keeps the current Repo Control `Rddd.dd_<lowercase_snake_case_slug>_...`
prompt/closeout artifacts discoverable while this repository transitions to
the canonical `M` standard. Legacy `R` IDs remain a distinct namespace and are
not translated into `M` IDs.

No universal parser was added for other project conventions. In particular,
Vocab App's numeric forms such as `004.6.13` remain unsupported: its configured
`milestones` root currently yields zero selectable candidates and warnings for
malformed/unsupported artifact-like filenames. This is an explicit limitation,
not a reason to rename or modify Vocab App files in R003.01.

## 4. Selection and Persistence

- `GET /milestones` is separate from the historical Git `/workflow` page.
- `POST /milestones/select` is CSRF-protected and revalidates repository key
  and generation under the existing repository action lock.
- No candidate is selected by discovery or sorting. An existing valid pointer
  is displayed as the current selection; invalid or stale pointers require
  explicit reselection.
- Pointer path:

  ```text
  ~/.local/share/repoctl/<repository_id>/milestones/selection.json
  ```

- Schema version 1 stores repository ID, milestone ID, and the
  repository-relative prompt path. The prompt path and configured root are
  resolved server-side; state cannot be stored inside the selected repository.
- Writes use a same-directory temporary file, flush and `fsync`, then
  `os.replace`. Reads and writes share the scanner artifact lock; scanner
  refresh preserves the milestone namespace.
- Selection remains isolated per configured repository, survives app
  reconstruction, and cannot mutate Git or project artifacts.
