## 2. Resulting Behavior

- `InformationStore` requires a caller-supplied database path and `StoreIdentity`. Initialization is explicitly disposable-fixture-only; opening an absent database does not create it.
- The schema uses application ID `0x52434953`, `user_version` 1, WAL, foreign keys, `synchronous=FULL`, `BEGIN IMMEDIATE`, and a 250 ms bounded busy timeout. Unknown application/schema IDs fail closed.
- Immutable UTF-8 revisions retain exact content and SHA-256. Prompt approvals and closeout submissions link exact revisions; closeout submission paths must match their linked revision source path. Workflow batches persist source events, reducer-derived projection, links, revisions, and idempotency receipts atomically.
- Workflow semantics remain owned by `repoctl.workflow.lifecycle`; the store delegates validation/reduction to the existing implementation. Dispatch decisions remain fixture records requiring explicit trusted fixture confirmation and do not authenticate an actor or grant operational authority.
- The importer consumes only caller-provided fixture bytes; it does not scan or read managed workflow files, registries, production databases, or state roots.
