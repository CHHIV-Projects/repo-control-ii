# M004.001 - Local Graphify Proof of Concept Closeout

## 1. Executive Decision

**GO TO INTEGRATION**, limited to a narrow, bounded, source-cited Python/JavaScript evidence subset in a separately approved M004.002. This is not production adoption, permission to expose Graphify directly, or a claim that its graph is complete/runtime truth.

Measured structural value justifies a thin integration: definitions, direct call/import neighborhoods, related test candidates, and bounded lexical/relationship context. The frozen supported set recovered **19/20 checks (95%)**. A bounded precision audit found **27/27 correct call/import assertions (100%)**; this is not whole-graph precision. Add/modify/rename/delete updates matched fresh builds, including oriented edges. Runtime IP egress was denied by an inherited kernel filter.

Important exclusions and integration requirements:

- Four of five difficult Flask/Jinja/browser checks were not recovered.
- Native MCP results are text, and missing/corrupt inputs and other errors can have `isError: false`. Do not equate protocol success with valid evidence.
- Native budgets are approximate, not a byte cap; one deliberately large response was **769,526 bytes**.
- Generic shortest paths are relationship paths, not necessarily call chains.
- Generated report community membership disagreed with graph/MCP numeric community membership. Leave communities out of the first subset.
- Generated HTML depends on a CDN library and is not a self-contained offline viewer. Keep it human-only and outside Repo Control's origin; full visual usability was not validated.

The integration milestone must validate its own failure, freshness, direction, and output-bound contract. If an operation requires substantial text parsing or another graph engine, omit/HOLD that operation rather than expanding the adapter.

**POC execution:** complete. **Formal Product Owner milestone acceptance:** pending. The workflow ledger is authoritative for submission status.

## 4. Privacy / Offline Method and Result

`unshare` and bubblewrap network-namespace probes failed with host permission errors. No privileged changes were attempted. The alternative was a local Python/ctypes launcher using the installed `libseccomp.so.2`.

Before executing Graphify, it installed inherited kernel deny rules for socket creation, connect/bind/listen/accept, and io_uring setup. Process launch closed nonstandard inherited descriptors. Self-tests in both the guarded process and its child failed attempted IPv4 socket creation with EPERM. **Result:** the tested code-only pipeline and native queries worked with outbound IP networking denied. Runtime traces showed no IP socket/connect activity. MCP's asyncio used AF_UNIX socketpairs and local one-byte `sendto` wakeups; those are local IPC, not outbound source transmission. The 20 cold-process CLI latency samples retained the guard but omitted strace to avoid tracer overhead.

No provider credentials, semantic extraction, LLM deduplication, model API, Cloud, hosted MCP, or PR-network tool was used. No runtime tokenizer download was required in this resolved environment. This demonstrates the tested configuration under enforcement, not a blanket no-network/telemetry guarantee for every Graphify dependency, optional feature, or future unguarded configuration.

## 12. Freshness and Identity Requirements

The source copy deliberately had no `.git`; generated graph metadata had schema/producer but **no `built_at_commit`**. `.graphify_root` identified the disposable source directory, and manifest/cache entries used source paths/mtimes/hashes. None of that independently proves the authoritative repository HEAD or dirty content identity.

A later adapter minimally needs:

- allowlisted repository key/path and selection/generation;
- source HEAD/branch for context plus a deterministic content fingerprint for dirty/untracked inputs;
- included files, exclusions, extraction options, producer/dependency/schema versions and algorithm;
- graph generation ID, build time/result, artifact hashes and source-to-graph identity;
- explicit missing/building/current/stale/failed/incompatible state;
- atomic validated publication and conservative stale marking when source/options/version changes.

Changing source must mark old evidence stale even if the stdio process hot-reloads by file mtime/size. Its successful reload is not a Repo Control freshness policy. Do not infer currentness from graph presence, same commit, node count, or process uptime. Never silently serve a failed/old graph as current.

## 13. Consumer Value and Provisional M004.002 Boundary

**Architect:** useful for locating subsystems, direct call/import neighborhoods, source-cited related tests, and bounded relationship context. Not sufficient for complete request-flow architecture, runtime blast radius, or test-coverage claims.

**Coder:** the same graph provides quick definitions, callers/callees, and candidate tests without repeated broad scans. Direct CLI is a viable fallback; targeted raw source reading remains necessary for gaps and critical findings. Do not append the graph to `coder-context`.

Provisional GO boundary, requiring its own approved prompt:

- Graphify owns extraction/resolution/native graph queries; Repo Control does not implement traversal, parsers, or community detection.
- Fixed local executable/environment and server-derived graph path; no second exposed service, arbitrary paths/tools/shell, semantic backends, PR operations, hooks, Git mutations, or agent lifecycle authority.
- Initial operations: stats, path-scoped node lookup, filtered neighbors, and tightly bounded lexical context. Generic relationship path may be added only with its meaning explicit; no promise of call-only path. Exclude community/report IDs and viewer integration initially.
- Architect MCP and a local Coder intelligence command should use the same selected repository, generation, bounds, provenance, freshness, and error envelope.
- Validate the measured native text contracts, explicitly normalize failure/ambiguity/truncation, and enforce independent byte/time/depth limits. If a safe thin operation cannot be demonstrated, HOLD it rather than pass through success-shaped native failures.
- Build/refresh authority is separately explicit; neither query consumer gains automatic build, lifecycle, or Git authority.

No interface, manifest service, application dependency, transport, or wrapper was implemented here.
