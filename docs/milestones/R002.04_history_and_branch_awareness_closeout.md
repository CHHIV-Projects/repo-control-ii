## 4. Recent History UX

History lists at most 30 commits reachable from the current `HEAD`, with short OID, subject, author, commit timestamp, decorations, and a merge marker/parent count. The page states that history is local and no remote refresh is performed. A command-output overflow is labeled incomplete rather than presented as a complete list.

## 5. Commit Detail UX

Selecting a full hexadecimal commit OID displays full/short OID, subject, author, author and commit dates, parent OIDs, changed-file status, comparison basis, and a bounded diff. The selected object is verified locally as a commit before detail commands run.

Root commits are compared with the empty tree. Other commits, including merges, use an explicitly labeled first-parent comparison. A truncated diff is marked incomplete; an undecodable diff is reported unavailable. Changed-file inventory overflow is separately identified.

## 6. File History UX

The Changes detail provides a link to committed history for ordinary tracked paths, including paths staged for deletion. Selection resolves only against the union of the index and current `HEAD` tree; arbitrary query text is never passed as a Git path. The history page distinguishes historical committed state from the current working-tree view and links from a file-history commit to the shared commit-detail view and back.

File history is limited to 30 commits and uses Git `log --follow` for the selected literal path. Rename following is Git's path-based heuristic and may not identify complex rename/copy histories; the UI states this limitation.

## 7. Branch Inventory UX

The Branches view lists every local branch up to the configured inventory limit, with name, current-branch indicator, tip OID, last subject/date, relationship to `main`, and upstream state. Detached `HEAD` is identified explicitly; no local branch is falsely marked current. Branch inventory overflow or malformed records fail closed.

## 8. Branch-vs-Main Semantics

For every local branch except `main`, counts come from:

```text
git rev-list --left-right --count refs/heads/main...<branch-ref>
```

The first (left) count is commits reachable from `main` but not the branch (**behind**). The second (right) count is commits reachable from the branch but not `main` (**ahead**). `main` itself is shown as the reference branch rather than as a meaningless comparison. If local `main` is absent, the page reports the relationship unavailable.

## 9. Fully-Merged-into-Main Semantics

“Fully merged into main” is shown only when `git merge-base --is-ancestor <branch-ref> refs/heads/main` succeeds. A non-ancestor is labeled “Not fully merged into main.” This is a Git ancestry fact, not a deletion recommendation; no branch-cleanup action or recommendation was added.

## 10. Upstream / Local Tracking-Ref Semantics

Configured upstream refs come from `for-each-ref` metadata. If the upstream ref exists locally, ahead/behind counts compare that ref with the local branch tip using `rev-list --left-right --count <upstream>...<branch-ref>`. Missing upstream configuration and configured-but-unavailable local refs are distinct states.

The page states that upstream comparisons use local remote-tracking refs, may be stale, and were not refreshed. This is separate from current local branch-vs-`main` ancestry. No fetch or other remote contact occurs.

## 11. Branch Detail / Comparison UX

Selecting a branch shows its local relationship to `main`, merge-base-derived changed-file summary, bounded diff, and bounded lists of commits unique to the branch and commits on `main` absent from the branch. The comparison is explicitly described as committed branch changes since the common ancestor (`merge-base` to branch tip), not a direct tip-to-tip diff. Missing common ancestry and incomplete file/diff evidence are labeled.

## 13. Bounds / Error / Incomplete-State Handling

The service reuses the existing bounded Git subprocess runner. Bounds are:

| Evidence | Bound |
|---|---:|
| Recent history / file history | 30 commits each |
| Local branch inventory | 256 branches and 256 KiB output |
| History and tracked/committed-file inventories | 1 MiB output |
| Commit / branch diff | 128 KiB each |
| Git stderr | 16 KiB |
| Git command timeout | 10 seconds |

Truncated histories are marked incomplete. Truncated changed-file lists are not parsed as complete. Truncated diffs may be displayed only with an incomplete warning. Invalid selections return a client error/not-found response; Git execution/evidence failures are presented as unavailable rather than as successful empty results. Commands use fixed argument arrays, full commit OID validation, branch tokens resolved against the local inventory, and literal pathspecs.

## 14. Backend Git Commands / Formats

The read-only service uses the existing bounded standard-Git-CLI adapter and machine-oriented formats:

- `git log` with bounded `--max-count`, ISO dates, NUL-separated metadata, and a record separator;
- `git cat-file -e` and `git show -s` for local commit validation/metadata;
- `git diff-tree` / `git show --first-parent` for per-commit files and diff;
- `git ls-files` plus `git ls-tree` for index/HEAD path validation;
- `git log --follow -- <literal pathspec>` for file history;
- `git for-each-ref` for local branch/upstream inventory;
- `git rev-list --left-right --count` for ancestry counts;
- `git merge-base` and `git merge-base --is-ancestor` for branch comparisons and merged status;
- `git diff` from merge-base to branch tip for branch changes.

All commands are argument arrays; the bounded runner uses `GIT_OPTIONAL_LOCKS=0`. No Git library or network command is used.

## 20. Known Limitations

- History is local to the current `HEAD`; it does not fetch or enumerate remote-only commits.
- `--follow` uses Git's path-based rename heuristic and is not a complete file-identity model.
- Upstream counts may describe stale remote-tracking refs.
- Branch inventory and diff limits can make evidence incomplete/unavailable; the UI marks those states.
- No merge graph, merge management, or branch/remote mutation is provided.
- An absent local `main` prevents branch-vs-main counts and merge-base comparison.
