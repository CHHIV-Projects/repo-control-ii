## Functional acceptance and stop conditions
- Exact parity of event IDs, original payloads, timestamps/order, repo/milestone/prompt identity, reducer-derived phase/open conditions/approval linkage and current projection across every applicable fixture; zero silent changes.
- No lost/duplicate acknowledged event under controlled multiprocess work, idempotent same-transaction retries and explicit errors on conflict/busy.
- Every fault/rollback test exposes either the complete old revision or the complete new revision; never a partly committed event/projection or fabricated success.
- Snapshot paging returns all expected events once, with explicit stale/invalid cursor behavior; full audit catches intentional event/projection corruption.
- A consistent disposable backup restores with integrity and replay parity.
- Any failure of these invariants is FAIL, not an excuse to enlarge scope. If foundational correctness fails or fixing it would entail substantial new storage machinery, STOP and escalate with a recommendation to reconsider SQLite or retain v1. No silent architectural optimization, custom recovery engine, or surprise integration.
