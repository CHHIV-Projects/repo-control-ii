## 1. Scope Completed

- Bound new file-backed Product Owner approvals to the canonical repository
  key/ID, milestone, prompt path, and SHA-256 of the raw prompt bytes reviewed.
- Revalidated prompt bytes at the lifecycle mutation boundary for both
  Approve & Start and standalone prompt approval.
- Promoted only one structurally valid, exact-scope source approval into the

  provenance checked by parity.
- Documented the shortest separately authorized deployment and fresh-candidate
  staging sequence. No live service or production candidate was changed.

## 2. Resulting Behavior

- A new approval carries a versioned `prompt_approval` evidence object. The
  workflow envelope remains version 1; runtime capabilities advertise the
  evidence schema separately. Stale, missing, unreadable, or changed prompt
  bytes fail closed with a reload/review message before approval or lifecycle
  start can be persisted.
- Import carries approval forward only when exactly one Product Owner event has
  valid evidence matching the imported repository, milestone, canonical prompt
  path, and raw-byte digest. The managed store records the source-event and
  digest provenance and links its own imported revision, decision, and prompt
  pointers atomically. Legacy chronology is preserved, and retries do not
  create duplicate authoritative decisions.
- Older approvals without proof, changed source bytes, malformed or conflicting
  evidence, and scope mismatches remain lifecycle-only/unapproved. The existing
  M010.025 explicit confirmation remains the separate candidate-local path for
  historical imports; it does not rewrite or retroactively authenticate old
  workflow events.
- The file-backed workflow has no immutable document revision ID, so the exact
  raw-byte digest identifies the reviewed content. The evidence records a
  reported Product Owner action; it does not authenticate the actor.

**B1 disposition:** New approvals made by the updated runtime now capture
exact-byte evidence that the importer can bind to its own revision. The
historical M010.024 B1 approval still has no revision or digest and remains
unprovable for exact bytes. It was not rewritten or backfilled; use only the
M010.025 one-time exact-revision confirmation on a separately authorized fresh
candidate when that legacy case applies.

## 4. Architecture / Integration Notes

The browser supplies the prompt identity rendered for review; the lifecycle
writer recomputes the digest while holding its mutation lock and persists that
evidence with the approval event. The importer validates the source event
against the exact imported prompt bytes before creating managed approval
records. The migration parity verifier checks the event link, decision,
selection, revision, and publication state; managed SQLite approval behavior
remains unchanged.

**Repository Intelligence: NOT USED** — the exact browser, lifecycle,
importer, and parity paths were directly inspected and covered by deterministic
source/runtime tests; a structural query was not materially needed. Graph
freshness/status was not queried for this bounded validation. Refresh was
considered unnecessary and not attempted; no refresh receipt or query is
claimed.
