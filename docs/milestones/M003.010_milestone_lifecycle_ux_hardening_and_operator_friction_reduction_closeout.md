## 3. Implemented UX

### 3.1 Server-authoritative refresh

The Milestone page polls a read-only workflow-fragment endpoint every five seconds. The endpoint reloads the selected milestone and workflow state, returns an uncached fragment, and rejects a stale repository or milestone selection. The browser replaces only the workflow panel when its phase, event count, or available-action set changes.

If the user has edited the form when newer state arrives, the form is not discarded. A visible warning marks the form stale and prevents submission until the page is refreshed. The event POST also checks the rendered lifecycle phase against current server state before writing.

### 3.2 Phase-aware actions and contextual fields

The event selector is derived from current lifecycle phase. Actions that require an eligible question, bug, closeout, resolution, or prior acceptance are omitted until the required context exists. The shared lifecycle engine remains the final validator.

Related-item, waiting, bug-classification, test-evidence, and Product Owner confirmation controls are shown and enabled only for relevant actions. The page clearly explains when relation-dependent actions are unavailable because no eligible item exists.

### 3.3 Summaries and aliases

Common actions receive deterministic, editable summary defaults. Related-item summaries include the related alias when exactly one eligible item exists; with multiple items, the selected alias is incorporated as the Product Owner chooses an item. User-entered summary text is preserved after validation errors.

Question and bug aliases are derived from workflow chronology, scoped to the selected milestone, and displayed beside concise summaries (`M003.010 Q1`, `M003.010 B1`, etc.). UUID event IDs remain authoritative in storage and in `related_event_id`; existing sidecars require no migration.

Single eligible related items are automatically selected. Multiple eligible items remain available in a readable alias-and-summary selector, with no arbitrary item preselected.
