## 2. Resulting Behavior

- **CIFS backup: PASS.** The supported backup command produced a verified backup and manifest on `/mnt/nas/repo-control`, mounted from `//192.168.1.171/ProjectBackups` as `cifs`.
- **CIFS restore: PASS.** The first restore and a subsequent restore after lock release both succeeded into a disposable local restore directory.
- **Sidecar cleanup: PASS for completed operations.** Staging and NAS contained no operation-owned partials or SQLite sidecars after backup/failure. After restore completion, the restore directory contained only restored databases.
- **Concurrent restore lock: PASS for safe exclusion on this mount/client/process scope.** The first process held the real manifest lock while its restore temporary had a zero-byte WAL and 32 KiB SHM. The competing process failed before altering the first restore, verified backup, or sentinel. The OS returned `errno=13` (`Permission denied`); the CLI reported the generic “manifest could not be locked” error rather than “another restore is already running.” This demonstrates fail-closed contention behavior on this tested setup, not cross-host locking.
- **Injected failure preservation: PASS.** A bounded exception after the second real snapshot validation returned exit code 2. The previously verified database and manifest remained byte-for-byte unchanged, the sentinel was unchanged, and no operation-owned partials or sidecars remained.
