# Milestone M008.003.001 — Architect Dispatch Ledger Persistence Across Repository Scans

## 1. Scope Completed

Reproduced and repaired scanner publication dropping the canonical per-repository Architect dispatch ledger. The fix preserves only the validated `architect_dispatches.json` artifact, serializes scanner publication and dispatch operations across threads and processes, and fails closed on suspicious ledger or backup state. No dispatch records were reconstructed or restored.

The confirmed code-level cause was `run_scan` replacing the repository state directory after copying only its known namespaces; the top-level dispatch ledger was omitted. The precise operation that triggered the reported production loss remains unproven.

## 2. Resulting Behavior

- Scans preserve a present ledger byte-for-byte and retain its file mode and timestamps after validating its schema, repository identity, records, size, and regular-file status.
- A missing ledger remains missing; a scan does not create an empty ledger.
- Symlinked, nonregular, oversized, malformed, or repository-mismatched ledgers stop publication without replacing the existing state.
- A stable advisory lock on the state-root parent, combined with the existing process-local lock, serializes scans and dispatch operations across processes using the same state-root location.
- A pre-existing scanner backup stops publication for operator review. A failed publication attempts to restore the prior directory; a failed restoration reports the remaining recovery location.
- Browser Generate Context and Snapshot creation continue through scanner publication without losing dispatch records.
- Workflow authority and dispatch approval semantics are unchanged.

## 4. Architecture / Integration Notes

Ledger preservation is narrowly scoped to the canonical dispatch file rather than copying arbitrary top-level state. The shared lock targets the stable parent directory of the state root, which is not replaced by scanner publication. Dispatch writes and reads that depend on the ledger use the same lock as scans.
