## Milestone Status

**Milestone:** M003.003

---

# 1. Purpose

M003.003 should reduce the Product Owner's role as the manual transport layer between ChatGPT / Architect, Product Owner, VS Code / Coding Agent, repository evidence, tests, and Git.

M003.001 / legacy R003.01 established canonical milestone discovery and explicit selection.

M003.002 established the six-phase lifecycle, durable `_workflow.md` sidecar, meaningful event/decision chronology, Product Owner approval boundaries, bounded bug handling, and phase reconstruction from durable events.

M003.003 should now generate bounded, copy/export-ready handoff packets for:

```text
Coder
Architect
```

The packets must assemble current authoritative material and deterministic evidence without creating a second editable source of truth.

Do **not** integrate directly with ChatGPT, Copilot, Codex, MCP, or another agent in this milestone.

---

# 2. Desired End State

The Product Owner should be able to open the selected milestone and request:

```text
[Generate Coder Packet]
[Generate Architect Review Packet]
```

Repo Control should assemble the current handoff from the selected milestone, approved decisions, standing project rules, closeout/evidence where appropriate, and deterministic repository state.

The Product Owner should no longer need to manually search several files and screens to compose routine handoffs.

---

# 3. Core Principle — Packets Are Derived Views

A handoff packet is **derived output**, not project authority.

Authoritative/current sources remain:

```text
configured governing project documents
selected milestone prompt
durable workflow sidecar / approved decisions
selected closeout
deterministic Git state
available test/evidence sources
```

Packet generation must not:

```text
create a second editable source of truth
change lifecycle
modify milestone artifacts
modify selection state
mutate Git
```

Repeated generation from unchanged sources should be materially stable and reproducible.

# 6. Packet Type 1 — Coder Packet

Purpose:

```text
Give the coding agent the current bounded instructions needed to work.
```

Use a predictable order:

```text
1. Project / repository identity
2. Selected milestone ID
3. Current lifecycle phase
4. Authoritative milestone prompt
5. Product Owner-approved binding decisions / lock-ins
6. Current blocking question / waiting reason, if any
7. Relevant standing coding-agent / workflow rules
8. Repository path
9. Validation/testing expectations available from source material
10. Explicit Git mutation prohibition
11. Source references
```

Do not normally include the closeout as Coder input unless the current lifecycle represents a bounded correction after review and inclusion is clearly justified.

A correction-mode variation may be derived from the same Coder Packet contract if low-cost; do not create a third packet type merely for that case.

---

# 7. Packet Type 2 — Architect Review Packet

Purpose:

```text
Give the Architect bounded evidence needed to review implementation.
```

Use a predictable order:

```text
1. Project / repository identity
2. Selected milestone ID
3. Current lifecycle phase
4. Original milestone objective / prompt
5. Product Owner-approved binding decisions / lock-ins
6. Relevant workflow events
7. Open questions / blockers / escalations
8. Closeout
9. Current deterministic Git state
10. Available test/evidence information with source labels
11. Known limitations / unresolved items
12. Source references
```

Do not silently represent coder-reported tests as independently verified.

# 8. Context / Size Discipline

Packets should reduce context waste.

Do not blindly concatenate every source.

At minimum define explicit inclusion rules.

Recommended direction:

```text
milestone prompt
→ full content unless a documented packet limit is exceeded

binding decisions
→ full current applicable text

coding_agent_rules
→ full content if reasonably sized

project_workflow
→ include only if useful to the Coder packet; preserve authoritative wording

closeout
→ full content for Architect review unless explicit size handling is required

workflow events
→ applicable binding decisions + unresolved/currently relevant events by default

Git
→ bounded deterministic summary, not full diffs
```

If any source exceeds limits:

```text
do not truncate silently
identify the omitted/limited source
state why
provide a safe alternate view/export if practical
```

Set and test explicit limits.

# 12. Lifecycle Awareness

Packet generation is read-only but should reflect current lifecycle.

Examples:

```text
READY
→ Coder Packet may state that the milestone is READY for handoff.

WAITING
→ Coder Packet must clearly state that implementation is waiting and why.

REVIEW
→ Architect Review Packet may state that the milestone is in REVIEW.
```

If a packet type is nonsensical in the current phase, either disable it with explanation or generate it with an explicit phase warning.

Do not generate false authorization.

---

# 13. Binding vs Non-Binding Decisions

Packets must distinguish:

```text
Product Owner-approved binding lock-ins
```

from:

```text
non-binding discussion / decisions
```

Coder Packet should include currently applicable binding lock-ins.

Non-binding events should only appear when relevant to current work or unresolved state.

Architect Review Packet may provide a broader bounded event summary.

Never elevate `decision_recorded` into a binding instruction unless the workflow record marks an approved lock-in.

---

# 14. Questions, Blockers, Escalations, and Bugs

Expose current unresolved workflow conditions.

Examples:

```text
open coder question
waiting reason
open escalation
unresolved out-of-scope bug
in-scope bug not yet fixed
```

Coder Packet must make blockers obvious.

Architect Review Packet should show current unresolved conditions and relevant disposition history.

Do not dump irrelevant closed historical events when a concise current state plus source references is enough.

---

# 15. Git Evidence

Git remains authoritative.

Architect Review Packet should include a bounded deterministic summary such as:

```text
branch
HEAD
upstream
ahead/behind using current local tracking refs
clean/dirty
staged / unstaged / untracked summary
changed paths where useful
```

Do not include full diffs by default.

Clearly state when ahead/behind uses local tracking refs and no remote refresh occurred.

Coder Packet may include repository/branch/HEAD identity without becoming a Git-status dump.

Packet generation must not execute Git mutation commands.

# 27. Stop / Escalation Conditions

Stop and ask the Product Owner before proceeding if:

- governing document configuration requires broad registry redesign;
- packet generation cannot remain derived/read-only;
- authoritative text would need to be copied into a second editable source;
- safe size handling would require silent truncation;
- safe source validation requires arbitrary filesystem access;
- direct ChatGPT/Coder integration becomes necessary;
- test evidence cannot be represented honestly without new test execution;
- stale repository/milestone requests cannot be bounded;
- scope expands into broad UI redesign;
- Product Owner Git authority would be reduced.

Do not silently redesign around these issues.

# 29. Completion Criteria

M003.003 is complete when:

- Repo Control generates a bounded Coder Packet;
- Repo Control generates a bounded Architect Review Packet;
- packets are derived from authoritative/current sources;
- governing project documents are resolved through safe server-controlled configuration;
- applicable binding lock-ins are included correctly;
- non-binding decisions are not elevated to instructions;
- current blockers/waiting conditions are visible;
- Architect packet includes closeout/Git/test evidence appropriately;
- source references are explicit;
- size limits/omissions are visible, never silent;
- stale repository/milestone requests are rejected;
- generation does not mutate Git, lifecycle, milestone artifacts, or selection state;
- focused tests pass;
- full suite passes;
- manual acceptance instructions are complete;
- no unauthorized Git mutation occurred.

The desired end state is:

```text
The Product Owner can generate a current, bounded handoff for the Coder
or Architect with one action, copy/export it, and stop manually assembling
context from multiple files and screens—while Repo Control remains a
deterministic transport/control layer rather than an autonomous agent.
```
