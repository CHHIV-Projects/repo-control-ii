# Milestone M007.004 — Bounded Architect Repository-Document Read Access

## 1. Scope Completed

Implemented a repository-scoped, read-only Architect capability for reading one explicitly selected current documentation file. The existing five-role `repo_document` contract remains separate and unchanged. Historical discovery and retrieval remain outside this milestone and are reserved for M007.005.

## 2. Resulting Behavior

- Public API: `GET /api/architect/v1/repository-document`
- Public MCP tool: `repo_read_document`
- Required inputs: repository-relative `path`, `expected_repository_key`, and `expected_generation`. The endpoint rejects unknown and repeated query parameters. Milestone-selection preconditions are not accepted or required.
- Allowed paths: Markdown, plain-text, or reStructuredText files below `docs/`, `.github/`, or `.repo-control/`; exactly root `README.md`; and `.agents/skills/<skill>/SKILL.md`.
- Path policy rejects absolute paths, traversal, backslashes, control characters, sensitive components and file suffixes, historical path components, unsupported roots and types, symlinks, directories, and special files. The reader anchors traversal to the selected repository using directory descriptors and no-follow opens.
- A source file may be at most 5,000,000 bytes. Returned content is capped at 128,000 UTF-8 bytes. Truncated output backs off an incomplete final UTF-8 character boundary and reports original size, returned byte and character counts, and truncation status.
- Content must be valid UTF-8 text; binary control characters and private-key material are rejected. File metadata and identity are checked around the read; observable replacement, disappearance, or mutation returns a conflict.
- Provenance includes selected repository key and ID, relative path, source type, current-working-tree indication, observation time, and size/count metadata. Git state is explicitly `not_collected`; Git metadata is not consulted to select content.
- Modified tracked and untracked current-working-tree files are readable. No directory listing, arbitrary filesystem read, source-code read, or historical artifact retrieval is exposed.
- Errors are explicit, including `invalid_document_path`, `document_path_not_allowed`, `historical_document_not_supported`, `unsupported_document_type`, `missing_repository_document`, `unsafe_document_path`, `repository_document_oversized`, `invalid_document_encoding`, `unsafe_document_content`, `repository_document_changed`, `invalid_precondition`, `stale_repository_selection`, and `stale_repository_generation`.
- The fixed MCP inventory now contains 16 tools, including 12 bounded evidence tools and the separate dispatch submission/readback tools.

## 4. Architecture / Integration Notes

The capability is implemented as a distinct `repository_document` response resource and a fixed MCP endpoint mapping. It does not extend the five configured governing-role documents, require an active milestone selection, or combine current-document reads with historical retrieval. Repository identity and registry generation are checked before reading.
