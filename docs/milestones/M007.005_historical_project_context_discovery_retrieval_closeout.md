# Milestone M007.005 — Historical Project Context Discovery / Retrieval

## 1. Scope Completed

Implemented repository-scoped, read-only Architect discovery and retrieval of historical project evidence. Added distinct historical search and selected-artifact read APIs and MCP tools, kept separate from current-document reading and active milestone authority.

Supported corpus:

- Prior canonical milestone prompts, workflow sidecars, and closeouts under the selected repository's configured milestone root, excluding the currently selected milestone.
- Supported text artifacts under the fixed `docs/history/` archive convention.

No registry schema or Vocab repository content was changed.

## 2. Resulting Behavior

- `GET /api/architect/v1/history/search` and MCP `repo_history_search` provide bounded lexical search or sufficiently narrow inventory, with optional query, milestone ID, artifact type, category, and limit filters.
- `GET /api/architect/v1/history/document` and MCP `repo_history_document` retrieve one explicitly selected historical artifact by repository-relative path.
- Discovery returns deterministic metadata and exact paths, not full document content. Ordering uses exact path match, exact milestone-ID match, descending lexical occurrence count, then path.
- Search is bounded to 2,000 candidates/directories, 50,000 directory entries, 300 text-file reads, and 16,000,000 scanned bytes; it returns at most 20 results and caps the response at 128,000 bytes.
- Retrieval returns at most 128,000 UTF-8 bytes and rejects source documents over 5,000,000 bytes. Size, returned bytes/characters, and truncation are reported.
- Results identify `historical_evidence`, current-working-tree provenance, repository identity, and explicitly state that history is not current governing or lifecycle authority.
- Secure traversal/read checks reject unsafe paths, symlinks, directories, unsupported/binary files, sensitive paths, and paths outside the allowlisted historical corpus. The APIs do not inspect Git history, source code, or arbitrary repository files.
- Historical artifacts do not become active milestone candidates. `repo_read_document` remains the separate current-document reader and continues rejecting historical artifacts.

## 4. Architecture / Integration Notes

Historical search/read are separate, fixed-purpose contracts rather than extensions to `repo_read_document`. Both require expected repository key and registry generation. They operate on the selected managed repository's current working tree; they do not use Git history, external services, semantic ranking, embeddings, or generic filesystem search.

The source policy is deterministic and does not add a registry-level historical-root field: prior milestone artifacts are rooted in the configured milestone directory, and archives use `docs/history/`. The currently selected milestone's files are excluded from historical discovery.

The MCP inventory contains 18 tools, including `repo_history_search` and `repo_history_document`. The Product Owner/operator reported that after refreshing the Architect connector, a fresh ChatGPT Architect session exposed both tools. Repo Control II live probes in this session used the current local stdio adapter against the deployed service.
