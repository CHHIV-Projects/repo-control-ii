## 2. Resulting Behavior

`shared/procedure/manifest.toml` identifies release `1.0.1`, overlay schema 1, the marker `<!-- repo-control-project-overlay:v1 -->`, each canonical source hash, and each managed target. The bootstrap renderer substitutes only the selected repository's registry-mapped overlay path and fixed workflow-core path. Rendering and lock ordering are deterministic.

`coder-procedure-status` reports `CURRENT`, `MISSING`, `STALE_VERSION`, `HASH_MISMATCH`, `OVERLAY_INVALID`, or `INCOMPATIBLE`, with affected paths and details. `coder-procedure-preview` is read-only, emits proposed diffs and hashes, reports no removals, marks the overlay untouched, and blocks invalid overlays, malformed/incompatible provenance, hash mismatches, path conflicts, and unmanaged edits. Exact existing canonical files can be adopted without rewriting.

There is no operational CLI/browser materialization action. The internal prepared materializer enforces centrally managed identity, repository/release binding, preview freshness, snapshots, conflict checks, per-file atomic replacement, and post-write `CURRENT` verification. It never modifies the project overlay or Git state. Multi-file writes are not transactional; on an I/O failure the documented recovery is to stop, inspect status/preview, and have the Product Owner/operator restore or reconcile generated outputs through ordinary reviewed Git changes before retrying.

## 4. Architecture / Integration Notes

The bundle is the single generic source; host and Skill files remain ordinary repository-local files for host discovery and review. Repository-specific product, runtime, data, testing, and deployment constraints remain local. The Repo Control II overlay has the required marker and `## Repository-specific rules` section and states that it cannot override generic authority.

The implementation accepts only centrally managed repository entries and re-resolves identity/mappings before inspection or preparation. Paths are repository-relative, validated against traversal, symlinks, non-directory parents, and non-regular targets. Preview is the only operator-facing reconciliation interface in this milestone.

Overlay validation is structural, not semantic; human review remains responsible for detecting local text that conflicts with generic authority. Host file presence does not prove fresh/resumed-session consumption or Skill invocation.
