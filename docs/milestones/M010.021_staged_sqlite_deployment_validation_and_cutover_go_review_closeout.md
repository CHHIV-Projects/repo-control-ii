## 4. Architecture / Integration Notes

The operator `store-authority prepare` path imports all registered v1 sources
and requires explicit v1-writer quiescence. In the disposable rehearsal, the
unbound v1 selection was copied into a distinct candidate state root, then
prepared, bound, previewed, and activated there. The candidate binding matched
the import report; the original live selection bytes and live authority state
were unchanged. This establishes fixture behavior only, not production
inventory parity or authority. The harness supplied the explicit
source-parity confirmation flag for the disposable activation flow; that flag
is an operator assertion, not independent parity evidence.

The recovery-point freshness guard is not a writer hold: fresh coverage
permits writes. A separate POSIX permission hold was demonstrated against the
managed application writer in the fixture. The hold was applied to the
candidate database files and directory, and the failed write left the event
count unchanged. Because the fixture process owned those paths, this proves
that ordinary application writes are denied by the mode bits, not that the
same owner is unable to change them. A production hold would need candidate
storage owned by an operator identity and read-only to the `chuck` service
identity until explicit release. The transient `systemd-run --user`
`ReadOnlyPaths`, `PrivateMounts`, `ProtectSystem=strict`, and
`BindReadOnlyPaths` probes all allowed writes here; do not rely on those user
manager settings.

The proposed browser unit runs as `chuck`, while `repoctl web` exposes no
`--state-root` option. Thus neither the proposed browser command's candidate
binding nor a production permission boundary is established. Source code uses
`state_artifact_lock` for file-backed workflow mutations, but there is no
supported CLI maintenance/drain operation. Lock acquisition can wait for
cooperating writes already holding it; it does not prevent new CLI invocations
or external edits, and stopping the Flask service is not graceful draining.
No live writer was stopped during this correction.
