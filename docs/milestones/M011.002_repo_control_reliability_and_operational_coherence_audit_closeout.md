Do not reopen that architecture decision without new evidence.

The seven §12.9 recommendations are disposed individually:

1. **Separate authority boundaries:** retain the current distinction between Coder authority, canonical published bundle integrity, selection generation, transaction confirmation, and backup coverage; do not add a blanket gate.
2. **Production-shaped integration harness:** include the bounded three scenarios in the roadmap below; do not grow a full state-combination matrix.
3. **Release-independent fixtures:** fix the hard-coded 1.4.0 helper before relying on the affected regression suites.
4. **Immutable deployment:** defer; current strict systemd sandbox and single-user operating context reduce the marginal benefit absent a mixed-version event.
5. **Operator-script hardening:** the historical missing-`rg` false PASS is fixed, but the current `systemd-analyze` check is too late in the install sequence; move required-tool and unit validation before service-file mutation in a separately authorized fix.
6. **Repository Intelligence:** use only when current, exact structural evidence can answer a consequential relationship question; rate ambiguous/no-edge outputs as no value and fall back to source.
7. **Migrated-state PO acceptance:** include imported history, explicit Review/Confirm, one-shot, backup, restart, and recovery in one bounded sanitized acceptance path; no production Apply is authorized by this audit.

The M011.001 [closeout](./M011.001_shared_procedure_transaction_and_deployment_compatibility_closeout.md) §12.7 graph nonuse was appropriate for that milestone's question and evidence. M011.002 re-evaluated Repository Intelligence because the active prompt required it; the current graph was not useful for the source/caller relation, and that result does not retroactively change the earlier disposition.

**F-02 — Required installer verification can fail after service changes (P1)**
- **Category/status:** source-confirmed operator defect; classification pending Product Owner; not runtime-reproduced.
- **Confidence/evidence:** high for ordering. The script has a `preflight` action that checks sources, but `install` does not enforce that action: it writes unit files and daemon-reloads before `verify_runtime` re-enters `verify_sources` and calls `systemd-analyze verify`; install may restart before that late check. If `systemd-analyze` is missing, `set -euo pipefail` exits nonzero, but only after changes and possible restart.
- **Affected PO operation:** installing/updating the procedure one-shot service.
- **Likelihood/impact:** low likelihood on a normal systemd host; high impact if a minimal PATH omits the verifier because service files may already have changed.
- **Existing mitigation:** the explicit preflight action is available and shell strict mode propagates failure, but the install action does not require the preflight; no restricted-PATH run was performed.
- **Effort/dependencies:** small (about 0.5–1 day); add a pre-mutation required-tool check and validate all candidate units before writing/reloading/restarting.
- **Recommendation:** fix in a separately authorized change; add a sanitized-PATH regression. Discovered bug event: `eee8b71a9c374f84b33f7307fe99ea7e`; classification/repair remain for the Product Owner.
