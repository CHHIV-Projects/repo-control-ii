# Milestone M010.007 — Product Owner-Controlled Accepted Closeout Publication to Git

## 1. Scope Completed

Implemented an isolated, fixture-only publisher for an immutable accepted closeout, a read-only Git target observer, a fixture-injected unregistered browser flow, and focused safety tests. The publisher does not stage, commit, push, or register production routes.

## 2. Resulting Behavior

- Publication accepts only the exact immutable `CLOSEOUT` revision at the canonical path derived from the selected prompt. Evidence must include a linked closeout submission, an exact-revision acceptance, a trusted fixture Product Owner decision, a later Product Owner closure, and a currently `CLOSED` lifecycle projection. A later reopen invalidates preview confirmation.
- Repository, milestone, source hash, target path, branch, HEAD, worktree/index fingerprints, and acceptance evidence are bound to the preview and confirmation. Reused request IDs with different inputs fail.
- Writes are restricted to a caller-supplied disposable worktree under the system temporary directory. The target is derived, symlinks and path traversal are refused, existing different bytes are never overwritten, and new files are created exclusively.
- The unregistered fixture UI separates preview from explicit injected fixture-PO confirmation, displays the source, Git snapshot, target status, and complete proposed diff, and exposes no stage or commit routes. Acceptance alone creates no file.
- Read-only inspection distinguishes materialized-unstaged, staged, and committed states. A related commit is recorded only when the observed commit tree contains the exact expected blob. Failed and drifted outcomes are retained for reconciliation.

The browser component is not registered in the production application.
